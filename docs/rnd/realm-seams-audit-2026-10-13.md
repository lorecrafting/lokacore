# Realm seams audit — dependency map and retrofit sizing (loka-kgd.150), 2026-10-13

Read-only audit of the batch M11 worktree (main + M11, head `42a5124`, kernel_api 1.83). Companion to the Fable R&D audit section 5 and the draft `owner-decision-realm-seams-2026-10-13.md` (read; nothing here contradicts its rules except the timing points in "Conflicts").

## Executive summary

1. The kernel is single-character by type (`World.character`, `World.body`, `runtime/decision.ts:126-127`) and by admission (`identity()`, `runtime/world.ts:187`: every command's `actor_id` must equal `world.character`); `bodyOf` (`:184`) is a comparison, not a lookup, and there is no inverse (`actorOf(body)`).
2. Rule code holds 28 `world.character` reads in 14 mechanics files plus 4 in `commands/actions.ts`, and 16 `world.body` reads in 11 mechanics files; `view/` holds ~58 more in 12 files. All are mechanical to retrofit: in single-player `actorOf`/`bodyOf` return the same ids, so the transcript known-answer suite guards byte identity.
3. Reactions run for the command actor (`runtime/proposal.ts:240`); only `quest_resolved` is re-attributed (`mechanics/reaction.ts:282`); 10 of 28 triggers declare a subject (`:180-191`). Making the subject total is S-M and the owner record wants it before 37a, which is an M12 row.
4. Kill credit already flows from the command actor (`combat/rule.ts:48` → `encounter.character_id`); the single-player part is the one-line contract in `combat/credit.ts:122-123`. Docs-only now.
5. The clock is already Realm-shaped (kernel pure by lint, `stepElapsed` authority-only); the one leftover is that `elapsed` carries a player `actor_id`. Defer.
6. Speech and audience need no code now; `AudiencePolicy` exists but creation refuses it (`foundation/creation.ts:24`). Threading the viewer through `view/` before M13 avoids writing 16/W15 visibility twice.
7. Receipts lack `result_digest` (`mobile/authority/local-story/store.ts:36-45`); replay re-decides and compares (`receipt-history.ts:30-40`) so the gap is trust of a stored response on the fast path. M, independent, needed before 48b or any Realm input.
8. Facts are cartridge-scoped (110 player, 56 instance across cartridges); no engine misfiling found, but NPC schedule `when` is evaluated as the player (`schedule/behavior.ts:51`) and the bank vault is an unlocked NPC pool: both need a decision before row 33.

## Risks and conflicts

- **Timing conflict.** The owner record says W1's subject rule is made total "before 37a merges"; 37a is an M12 row, so RS-1 and RS-4 must land ahead of 37a (inside M12), not between M12 and M13 as the batch framing says. Either order 37a last in M12 or run RS-1/RS-4 first.
- **"No row rewrites untouched sites."** The record's rule 1 forbids rewriting old reads outside the touched function; RS-2/RS-5 are that rewrite by design. The record needs one line naming the seams batch as the exception.
- **Schedule `when` as the player** (`schedule/behavior.ts:51`): neither the record nor rule 1 covers an NPC job with no owning character. Options: evaluate instance facts only (loader check, TS + Elixir parity, S+S) or document as Story-only. Needed before 33 (witness `when` on player facts).
- **Vault theft.** Row 33 theft on the vault NPC drains every player's `savings` mirror; G7 `get` lock on the vault must be in the 33 brief.
- **RS-7 save format.** Explicit refusal of `loka-save-v2` discards the owner's device saves (forward-development decision allows it; say so).
- **Budget drift.** If `actorOf` or threaded actors add query steps, transcripts break; keep lookups uncounted.
- **Elixir parity** is untouched by RS-1 to RS-6 (no schema or loader change); only the schedule `when` option adds a declared differential (`bin/contracts.exs`).
