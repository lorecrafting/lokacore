## What must be true (from the spec, before the diff)

1. Rooms are definitions keyed by DefinitionRef; runtime entities get UUIDs from IdSource, never
   host entropy (03 §2-§3; 01 A8; numeric-profile.md IdSource). Two runs with the same replay
   inputs mint the same ids.
2. Containment is one authoritative relation per entity (03 §23); rules are pure
   `decide(state, command) → proposal` and never write memory (ADR-072; 04 §4-§5); a rejection
   consumes nothing (04 §5.0); unknown command types and capabilities fail before any rule
   (04 §3; 14 §R5 properties); the result is bounded (14 §R5).
3. Rejection codes are the 04 §7 machine codes in `error_registry.json`.
4. A Connection is a typed traversable relation whose later attributes (directed/undirected,
   labels, travel policy and cost, mode, barrier state, ports) and a shared Barrier state must
   remain expressible (21 §5; 05 §17, §25). Room keeps descriptions/variants, contents, details,
   tags (21 §5-§6).
5. The compiled cartridge's `format` is the hash domain; a shape change takes a new tag and the
   v1 known answer is untouched (cartridge.schema; 05 §11). Compiler stages resolve local refs,
   validate capabilities and localization (05 §8); unregistered fields are errors (05 §5); text
   is stable string ids (05 §18).
6. The loader re-checks at the trust boundary what the compiler checked (05 §20; CAR-07).
7. Capabilities own what they introduce (05 §6); rule modules stay TypeScript-only (ADR-074) and
   the foundation (IdSource, encoding, compose) stays shared.
8. ADR-075: one `trace.run` header (RunIds) then `trace.command` entries with ordinals 1, 2, …
   without gaps, rejections and faults recorded, `command.id == ids.command_id`, the commit
   matrix, no time/host field in game_trace, RNG state stored whole, `kernel_version` with
   `-dirty`, every record validated before it is written with a planted invalid record, the
   §6 leak test, `input_digest` for a failed load with its known answer, delta digest known
   answer computed outside the kernels, `run_id` not re-minted on replay.
9. GameView is a host-neutral projection with deterministic ordering (04 §14-§15).
10. Owner records verbatim; the 10,000-sequence cross-check location decided (owner decision
    R5 setup); AGENTS.md "Writing tests" holds for every new test.

## Findings

- **F1 (should-fix) `kernel/ts/play/main.ts:75,136-139`**: `--replay` regenerates the header
  under the *current* `kernel_version` and compares bytes, so the comparison fails at line 1
  whenever the tree differs from the recording. Scenario: record a transcript on a clean HEAD,
  edit `rules/movement.ts` to fix a bug, run `--replay` to prove the fix: exit 1, `replay
  differs at …:1`, whether or not any decision changed. Reproduced with only an untracked file
  present. ADR-075 §4's "the inputs reproduce the failure before the fix and not after" cannot be
  run with this tool. Fix: on replay, regenerate under the header's `kernel_version` (as `run_id`
  and seed already are; replay writes nothing, so no record claims a wrong revision) and print
  the running kernel beside the result; or compare with the header's ids excluded and report an
  ids difference as its own outcome.
- **F2 (should-fix) `kernel/ts/src/world.ts:30-33`**: the lockdown does not bind the
  registration point. Scenario: in S4 an agent writes `containment: (w, c) => { … }` inline in
  `RULES`; it is neither named `decide` nor `Rule<…>`-annotated, and `rules/**` lints do not
  apply to `world.ts`, so it may mutate state through a cast; `ast-grep scan` and `tsc` both
  pass (verified with a state-mutating inline rule). The owner asked for lint that makes the
  right way the only way. Fix: one ast-grep rule that every value in the `RULES` object literal
  is `$MODULE.decide` and every `$MODULE` import in `world.ts` comes from `./rules/`.
- **F3 (should-fix, owner/PM ruling) `protocol/cartridge.schema.json:7` versus
  `protocol/room.schema.json:4,7`**: the frozen rule says "any change to a variant's shape takes
  a new tag"; room.schema and the PR say details, tags, contents, variants and `barrier` "join as
  optional fields". Both cannot hold. Scenario: S7 adds `barrier` to Connection; under the
  cartridge.schema text that is `loka-cartridge-v3`, and S3 and S4 each mint another tag, or the
  developer adds it under v2 and the text is fiction. Decide now and write it in
  cartridge.schema.json: recommended, an optional field added to a definition kind keeps the tag
  (an artifact without it has the same bytes, hash and meaning); a required field, a removed
  field, a changed meaning or a new top-level field takes a new tag.
- **F4 (should-fix) `docs/spec/conformance/numeric-profile.md:59-66`; convention at
  `kernel/ts/src/world.ts:44-51`**: the initial-state ids (nil CommandId; ordinal 0 the
  CharacterId, 1 the body, then rooms in DefinitionRefString byte order) are a foundation
  convention recorded only in a code comment. The profile's IdSource text covers ordinals "per
  command … within a decision"; world creation is neither. ADR-074 keeps IdSource in both
  kernels, and `initial_state: fresh` in the trace header is the complete replay input only if
  this construction is frozen. Scenario: S4 places items and allocates their ordinals after rooms
  in one order, the Elixir foundation twin or a snapshot tool in another; the same fresh world
  gets different ids on two hosts and every transcript stops replaying across them. Fix: an
  additive amendment beside the CommandId one, reserving the nil CommandId for initial state and
  fixing the ordinal order per kind. Soundness verified (no derived CommandId can be nil).
- **F5 (should-fix) `protocol/text.schema.json:81`; `kernel/ts/src/cartridge.ts:216`;
  `lib/loka/content/checks.ex:118`**: TextCatalog promises "every text key a definition uses has
  an entry", but only room `title` and `description` are checked; ActionDefinition `label` and
  `accessibility` are not. Scenario: a v2 cartridge with `actions/talk.json` (`label:
  actions.talk`) and no such key in `text.json` compiles and loads; when S5 shows actions, the
  player reads `actions.talk`. Fix: check action keys in both compiler and loader (a few lines
  each), or narrow the contract text to room keys until then.
- **F6 (should-fix) `lib/loka/content/compiler.ex:42-43`; `test/loka/content_rooms_test.exs`**:
  the "v2 exactly when the source has rooms, an entry or a text catalog" rule is tested on rooms
  only. A mutant keying v2 on rooms alone passes 32/32. Scenario under that mutant: a source with
  `text.json` and an `entry` but no rooms compiles to v1 and both files are silently dropped
  from the artifact. Fix: one compiler test, `text.json` (or `entry`) without rooms →
  `SCHEMA_VIOLATION cartridge.entry missing_property` (or v2 with an unresolved entry).
- **F7 (should-fix) `kernel/ts/play/main.ts:25`; `kernel/ts/test/play.test.ts:133-157`**:
  ADR-075 §3 says the first producer of `input_digest` adds its known answer; none is added and
  no test reads `ids.input_digest`. Scenario: a later edit digests the canonical cartridge
  (equal to `content_hash`) instead of the file bytes; the diagnostic can no longer be matched to
  the file it is about and nothing fails. Fix: in the leak test, assert `ids.input_digest` equals
  a `node:crypto` SHA-256 of the artifact file bytes (the test already computes hashes that way),
  or a fixture.
- **F8 (should-fix) `docs/spec/00a-chapter-one-content.md:521` (and IMPORT.md amendments)**:
  the frozen room shape (`title`/`description` TextKeys, `exits` keyed by direction, `text.json`,
  `entry` in `cartridge.json`) diverges from 00a §12's `components.description.short/long`,
  `connections` and `localization/en.yaml`, and no amendment records it, unlike R4's note for
  facts, policies and actions (spec README §11; 00a is on the normative content pull list).
  Scenario: the S3 developer reads 00a §12's `description: {short, long, variants}` and builds
  variants against a shape that does not exist. Fix: extend the 00a §12 amendment note (owner
  decision reference as R4 did) naming the frozen room, text and entry shapes.
- **F9 (nit) `kernel/ts/src/world.ts:81-82`**: the `output_bytes` guard survives deletion. It is
  unreachable with the two rules (1 MiB; a move is a fixed-size decision), so it cannot be
  tested honestly without a fake rule. Say so in a comment, and test it in the slice whose rule
  can produce variable-size output (S5).
- **F10 (nit) `kernel/ts/play/obs.ts:41,49`; `kernel/ts/test/play.test.ts:147`**: the serial
  half of the ADR-075 §6 leak test is satisfied by setting `ANDROID_SERIAL` to the planted
  string, so it proves only that the env value is stripped; a serial-shaped string reaches the
  record on a host without that variable. Acceptable on Node with the `ponytail:` comment; the
  device host slice must replace it with a real source.
- **F11 (nit) `kernel/ts/src/cartridge.ts:208`, `kernel/ts/src/decision.ts:68`**:
  DefinitionRefString formatting written twice; the loader can import `refString`.
- **F12 (nit) `kernel/ts/play/main.ts:140`**: a header-only transcript reports `replay: 1
  records identical`, vacuously true. Say `0 commands` so a truncated transcript is not read as
  a passing replay.

A4 — should-fix — A valid zero-command transcript loses the initial world identity

Failure scenario:
