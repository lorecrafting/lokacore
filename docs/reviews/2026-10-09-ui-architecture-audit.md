# Book UI architecture audit (read-only, main @ 84b32e74, 2026-10-10)

Scope: `mobile/app/book/*`, `mobile/app/stories/*`, `mobile/app/.storybook/*`, `lint/rules/mobile-book-*`, `docs/BOOK-UI-COMPONENTS.md`.

## 1. Single source of truth: YES, with four story-only wrappers (none hides logic)

The game renders `Book` (`App.tsx:268`) → `BookView` → `Body`/`Combat` → page components → leaf components. Every story imports those same files:

- Leaf stories (`stories/{ActionCard,Control,EntityLine,LogLines,Footer,Tip,LetterTile,Riddle,PageFoot,ContinueButton,VerbLine,StatusLine}.stories.tsx`) import from `../book/*.tsx` directly; `catalogue.test.ts:30-50` fails if any exported component has no importing story.
- Page stories render the real `BookView` (`stories/screen.tsx:69-92`) over views generated by replaying tap routes through the real `Book` in Node (`stories/scenarios.ts`, harness `book/__tests__/polish-book.test.ts:59`); `stories.test.ts:8-21` fails when committed views drift from the code.
- Live stories mount the real `Book` over a real SQLite save (`stories/Live.stories.tsx:18`).
- Decorator supplies the palette through the same `PaletteContext`/`useFocusRing` the Book uses (`.storybook/preview.tsx:3-4,99-112`).

Story-only code (all presentational scaffolding, no logic copies):
- `stories/Page.stories.tsx:17-30` `Framed` (100vh frame + `RunningHead`) and `Prose` filler; the Storybook docs list shows the component as "Framed", not "Page".
- `stories/ActionCard.stories.tsx:42-50` `WithUnavailableNote` hand-writes the unavailable note (`<Text style={note(c)}>Buy a lantern: sold out</Text>`) because no component exists for it (see §2).
- `stories/PageTurn.stories.tsx:20-36` `Turning` duplicates `page-turn-preview.tsx:12-27` line for line (same two pages, same toggle). Two copies of one driver.
- `stories/screen.tsx:26-47` `screenFrom` rebuilds the presenter's `Screen` shape by hand (fixed field list). A new `Screen` field is silently `undefined` in every page story until someone edits this file; TypeScript catches additions only when they are required.

Verdict for the owner: changing a component changes the stories and the game; no fork. The hand-built `Screen` in `screenFrom` is the one place a story could drift from the game.

## 3. Variant model: ad hoc booleans, but few and consistent

- `Page`: `fixedTitle?`, `centred?`, `scrollToEnd?`, `foot?` (`pages.tsx:189-197`). Catalogue names these as states ("scrolling title, fixed title, no title, centred"). Booleans match one-of-a-kind states; fine.
- `Control`: `disabled?`, `onInk?: true` (`pages.tsx:88-93`). `onInk` is a colour variant expressed as a boolean.
- `EntityLine`: `rest?`, `note?` (content, not variants). `LetterTile`: `used`. `StatusLine`: `locked`, `pending`.
- No `tone`/`size` enums anywhere; the only enum-like thing is `band(c, tone)` (`pages.tsx:19-20`) for resource tone, which both Status and Character use.

Proposal (no new machinery): keep booleans where a component has one binary state (`disabled`, `used`, `locked`). Where the catalogue lists a *set* of states on one row, make it one prop: `ActionCard` gets `reason?: string` (renders the unavailable note instead of the card: one component, two catalogue states, the story stops hand-drawing it); `Control` `onInk` becomes `tone?: 'ink' | 'paper'` only if a third surface ever appears (today: leave it). Add a `Note` export in `lines.tsx` (`note(c)` Text; props `children`) so empty states and "save not confirmed" are one component and one story, and the Status/Ancestry pending shapes converge. Rule to write in the catalogue: "A state the catalogue lists is a prop on that row's component, never a sibling drawn by the page."

## 4. Token discipline

- Raw colours: only in `tokens.ts`, `stories/system/palette.ts` (dev chrome, guarded by `system.test.ts`, spec §2 says not Book UI: acceptable), tests, and the dev panel. Good.
- Unused tokens: `size.speechBar` and `type.speaker` have zero consumers (catalogue Log line row says the speech line "waits until the log projects a speaker"). `space.block` is used in 2 places only; `size.card` 2; `radius.tag` 1. Nothing else dead.
- Token leaks the rule does not catch: string sizes (`'100%'`), `fontWeight`, `fontStyle`, `textAlign` (fine, layout), `textDecoration*` (`lines.tsx:9-12`). The catalogue sanctions the entity-line underline, so this is a documentation/token gap rather than a defect: a `type.named` (weight + underline) token would let the rule cover it.
- `Status.tsx:83` `width: '100%'` is a layout hack to force the pending line onto its own row; a `Note` component below the row would remove it.
- Storybook manager theme reads `tokens.ts` (`.storybook/manager.ts:4-7`); the `Palette` toolbar lists `Object.keys(color)` (`preview.tsx:20-27`), so a new palette appears automatically.

## 5. Storybook coverage

Stories exist for every exported component (test-enforced). Gaps:

- No play test where behaviour matters: `Riddle` (only `AnswerInProgress` picks tiles; no Backspace/Clear/Submit path), `NpcPage`/`NoticePage`/`ItemPage`/`MapPage`/`CombatPage`/`SectionPages` page stories have no `play` except RoomPage `FirstRoom`/`Reworded` and ChapterTitle. The `label-in-name` `afterEach` (`preview.tsx:79-93`) and axe run on all, which covers names and contrast, not taps. `Footer` `Held` covers the drag; `BarredExit` has no play (the refusal line is the behaviour).
- Water banner (`Body.tsx:40-45`) and `Fault` have no leaf story; `Fault` appears in `Pages/Recovery`.
- Catalogue vs code: (a) Control row lists labels that are also literals in code (sync by hand); (b) Log line row describes the speech line and its tokens with no consumer, contrary to the catalogue's own "a new component needs a real consumer" rule; (c) "Not adopted … shop price rows" contradicts `Menu.tsx:253-264` which renders shop rows as notes; (d) no row for the empty-state note, the unavailable-action note, the water banner, or the pending line; (e) `Fixture link` row has no story and no consumer (declared). (f) Storybook lists `Book/Page` as "Framed" because `meta.component` is the wrapper (`Page.stories.tsx:43-44`).
- `Catalogue.mdx` renders the doc raw: fine.
