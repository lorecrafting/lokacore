## What must be true (written before reading the diff)

From 00 §4.1 (scan row), 21 §5-§6, 04 §5.0, §15, §19, 05 "Capability version immutability",
10 §2 / 14 §R2, and the S4 owner decision (touch links):

1. `scan` lists, per exit of the actor's room in a fixed order, the direction and either the
   door that bars it (closed or locked) or the destination's title and its visible NPCs and
   items: the same set and order the GameView shows for a room, nothing inside containers.
2. It is a zero-time read: no ops, no RNG, no clock, no event; nothing that can throw out of
   `step`.
3. Sight never disagrees with walkability: an exit movement refuses for a barrier shows the
   barrier.
4. The ActionSet offers `scan` exactly where admission accepts it (shared eligibility), and
   `movement@1`'s existing commands and event stream are unchanged (an additive change to a
   pinned capability, not a reinterpretation).
5. The loader rejects a dangling touch-link target exactly where the compiler does: same
   texts, same self rule, same target scope (room texts: the room's details plus the
   cartridge's items and NPCs; entity texts: items and NPCs), same data.
6. `implemented_in` states something true, and a test fails when it does not.
7. The mobile import rules catch `require(...)` and `jest.mock(...)` specifiers crossing a
   boundary without flagging ordinary strings inside those calls.
8. Existing fixtures and transcripts unchanged except where a listed reason requires it; every
   cartridge still loads and plays.

## Checks against the list

1. `movement.ts` `sight` filters `world.entities` by `containers[id] === there`, the same
   selection and order as `view.ts` `within`, so container contents are excluded (tested: the
   oil in the satchel). The body is not in `world.entities`, so a self-loop exit cannot list it.
2. `decide` returns `accepted(world, 'scanned', [], [])` before touching the payload, like
   `look` without a target. The containment test asserts the full decision (no ops, events,
   effects, `rng: SEED`) and unchanged state.
3. `sight` calls `passage`, the same function movement's admission and the GameView exits use.
4. `scan` joins the engine `VERBS` table with target `none`, no input; admission and the
   ActionSet share that table, as for `look`. Additive under `movement@1`: `move` and
   `entity_entered_room` are untouched and no existing transcript changed. No cartridge is
   published yet, so 05's immutability rule is not engaged; `wait`/`open` set the same pattern.
5. `cartridge_links.ts` against `lib/loka/content/links.ex`: same regex; `[w]()` yields target
   `""` on both sides (JS `??` keeps `""`, Elixir's `[""]` clause); a room title, description,
   variants and each detail's description and variants use the room's details plus entities;
   entity short, room line, description and room-line variants use entities only, self the
   entity key; a target-less link in a room's own text reports `[words]`. Both skip barrier and
   recipe texts. The warning staying compiler-only is right: the loader has no warning channel
   and the DiagnosticCode text says so.
6. The meaning changed to "where a check by this id runs today" (`elixir_and_typescript` /
   `typescript` / `none`). `registries_test.exs` derives the placement from the code
   (`Invariants.check/2` clauses; `invariant_peer.ts` asks `check` and `holds`, which throw
   `unknown invariant` for unknown ids). Values checked by hand against both files: they match.
7. `module-specifier.yml` accepts `template_string` and the listed call forms; the string must
   be a direct argument (no `stopBy`), so the valid cases' `jest.mock(path, () => ({ label:
   '...' }))` and `jest.fn('...')` stay clean.
8. See "Changed expectations" below. CI green on `870cca1`; locally `npm test` (193 pass),
   `mix test` (204 pass), `ast-grep test --skip-snapshot-tests`, `bin/lint_red_controls.sh`.
