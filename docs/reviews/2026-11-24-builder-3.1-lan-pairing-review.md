## Must be true (written before the diff)

1. Off by default: no `--lan`, preview binds 127.0.0.1 and the author server sees no new header.
2. Token: 128 random bits, minted per start, never on disk, dead with the process.
3. `?pair=` compares in constant time; a match sets `HttpOnly; SameSite=Strict; Path=/` and 302s without `pair`; a miss is 403 with no cookie.
4. Every non-loopback request needs the cookie, on every path, upgrades and SSE included.
5. The author server takes a LAN Host, or a non-GET with no Origin, only with the matching header; it stays on loopback.
6. After 8 idle hours `--lan` is off for the LAN side, and the terminal says so.
7. Metro (and the panel) stay loopback-only.

## Findings

### Blocker 1: idle expiry leaves live LAN streams flowing

`mobile/app/pairing.cjs:17-25`, `mobile/app/preview-server.cjs:107`.
- Expiry only flips `off`. Nothing tracks or destroys the non-loopback sockets already open, so the SSE stream (`/__author/events`) and Metro's websocket keep flowing.
- Shown with `IDLE_MS` set to 20 s in a scratch copy:
  1. Paired, then held `curl -N` on `/__author/events` from the LAN IP.
  2. Waited until the terminal printed "--lan is off", and confirmed a new request with the cookie got 403.
  3. Edited a room on the Mac. The open stream received the new compile (544 to 2711 bytes).
- "Off" still streams source changes to any device that paired earlier. The fix is to destroy the LAN sockets when the guard goes off.

### Should-fix 2: the pairing link opened from another site lands on 403

`mobile/app/pairing.cjs:37-40`.
- Tested in Chrome (browser-use): a page on `localhost:29150` linked to `http://<LAN IP>:29106/?dev=1&pair=<T>`, with no cookie stored beforehand.
  1. The click stored `loka_pair` (Strict, HttpOnly).
  2. The redirected load of `/?dev=1` answered 403. A reload also answered 403.
  3. Only a navigation from the address bar loaded the page (200).
- The phone's first sight is a 403 page that looks like a failed pairing. One fix: answer a correct pair with a 200 page that does a same-origin `location.replace`, which keeps Strict.
- iOS Safari not tested.

### Should-fix 3: the docs promise Build on the phone and never say it cannot save

`docs/guides/writing-the-game.md:50-51`. The section says the phone can "use the Book with Build" and does not say that a paired phone shows "The save could not be opened" (loka-xetp3). Its line "a page already open keeps its live connection" also changes once Blocker 1 is fixed.

### Nit 4: the preview's wiring has no automated test

`mobile/app/preview-server.cjs:49-50,63,87,100`. CI would stay green if the `refused` check, the upgrade guard, the `forwarded` spread or the bind choice were dropped. Today the only proof is the developer's hand check and this review's curl.
