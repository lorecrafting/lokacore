# Review: R5 S2b short references in cartridge source (PR #37)

- PR: [#37](https://github.com/lorecrafting/lokacore/pull/37), branch `r5-s2b-short-refs`.
- Commit reviewed: `7c18373` (merge of main into `6543af0`).
- Reviewer: a fresh Claude Code agent (Opus) that authored none of the work.
- Verdict: **CHANGES REQUIRED** (one blocker, a one-line test; one should-fix).
- Read first: the owner decision (short refs, 2026-09-25), 00a §12 and its S1 amendment,
  AGENTS.md "Writing tests", docs/lessons/contracts.md.

## What must be true (before the diff)

1. Every compiled artifact and known answer is byte-identical; frozen fixtures untouched.
2. Full DefinitionRef objects still compile with the same diagnostics as before.
3. A short ref expands to {this cartridge's id, version, the field's kind, key}; an unknown
   one is UNRESOLVED_REFERENCE at the field's path with the full target.
4. The kind comes from the field, so a key defined under another kind never resolves.
5. The TS loader and the artifact contract never see a short ref.

## Checked

- 160 Elixir tests pass. No file under `protocol/` or `kernel/` changed; both known answers
  (ashmere_hello, ashmere_details) still match, and ashmere_rooms keeps full refs.
- The source schema is an in-memory patch (`compiler.ex:204`, DefinitionRef becomes
  `anyOf [Key, DefinitionRef]`), not a schema file, so there is nothing to regenerate or
  drift-check (TS types, docs). The TS side reads only artifacts and fixtures, never source.
- Probes (scratch script): a short quest ref three levels deep
  (`any > not > all > quest_state`) is UNRESOLVED at `...items[0].item.items[0].quest`; a
  short entry naming a non-room is UNRESOLVED `room/r`; `"to": 5` is SCHEMA_VIOLATION
  invalid_type; a manifest with a bad id plus short refs gives only the id diagnostic;
  malformed full refs (missing `key`, bad `kind`) and a cross-cartridge full ref give the same
  diagnostics and paths as on `main`; a room detail keyed `exits` compiles.
- Mutations (throwaway worktree, removed): drop `has_item` from `@ref_fields` (3 fail); disable
  the exits clause (2 fail); entry kind `policy` (2 fail); entry not expanded (2 fail);
  version hard-coded (5 fail); drop `quest_state` from `@ref_fields`: **all pass** (B1).

## Findings

**B1 (blocker) `test/loka/content_test.exs:279`.** No test covers a `quest_state` short ref.
With `"quest_state" => "quest"` removed from `@ref_fields` (`checks.ex:12`) the suite stays
green, and a policy `{"op": "quest_state", "quest": "q", "state": "active"}` compiles to
`{:ok, artifact}` carrying `"quest": "q"`. Fix: add that node to the test's `all` items and
expect `UNRESOLVED_REFERENCE` with target `c@1.0.0:quest/q`.

**S1 (should-fix) `lib/loka/content/checks.ex:57-63`, `compiler.ex:204`.** Source now accepts
a Key at every DefinitionRef, but expansion is a hand list, and the `op` and `exits` clauses
return without recursing into the node's or room's other fields. Scenario: S3 adds a
condition (a policy node) to RoomDefinition; `"fact": "x"` there passes the source schema,
is not expanded (the exits clause returns the room first), and `compile/1` returns an
artifact with a content hash. Verified with the B1 mutation: the TS loader then rejects it
(`SCHEMA_VIOLATION invalid_type` at `.cartridge.policies["c@1.0.0:policy/p"].root.quest`).
So the known gap fails loudly, but at load, after the compiler has emitted an artifact that
breaks its own contract. Cheapest fix: a line in `docs/lessons/` (a new source ref field
must be added to `@ref_fields`/`expand/2`, with a short-ref test). Making the two clauses
recurse is sturdier, but a generic recursion into `details` would hit the exits clause for
a detail keyed `exits` and crash, so it has to follow the room's shape.

## Judgments on the decisions

- Every reference-typed source field accepting a short ref, kind from the field, short means
  this cartridge, cross-cartridge needs the full form: sound; ambiguity is impossible by
  construction (the same key under another kind resolves only under the field's kind).
- Malformed short ref is SCHEMA_VIOLATION (`pattern_mismatch` at the field): right.
- Invalid manifest expands nothing: right; the build fails on the manifest alone, with no
  cascade of short-ref noise.
- Converting ashmere_details and ashmere_hello and keeping ashmere_rooms on full refs: right;
  both forms stay covered by known answers.
- The 00a amendment: acceptable. It follows the S1 amendment's precedent in the same place,
  cites the owner decision, and the spec text and code land together in one reviewed PR.
- Over-engineering: none found.
