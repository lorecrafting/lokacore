## Findings

**S1 should-fix**: `mobile/app/book/joystick.ts:7-16,27`. Eight 45° sectors, but the protocol allows no diagonal exits (`protocol/room.schema.json` exits: N/S/E/W/up/down; a `northeast` key is rejected in `test/loka/content_rooms_test.exs:148-156`). Half of every drag circle can never pick anything. At Ferry Landing (north only), a drag 30° right of straight up (`pick(5.8, -10, ['north'])`) returns `null`: no path lights and release does nothing, while the mock (`playable-src/room.js:240`) uses four 90° sectors and walks north. Fix: four cardinal 90° sectors (delete the diagonal `ANGLE` entries; `MapDrawing` needs only the four). This flips `joystick.test.ts:13`, which currently pins the dead zone. Snapping to the nearest existing exit is not needed: 90° quadrants match the mock and the simple-feel rule.

**N1 nit**: `mobile/app/book/Footer.tsx:104`. The right rule is a later sibling of the map container, so it paints over the zoomed backing disc. In `footer-zoomed.png` the right rule runs through the map beside the stair nodes, while the left rule is hidden. The mock's backing covers both. Render the map container above the rules (for example `zIndex: 1`).

**N2 nit**: `mobile/app/book/Footer.tsx:85`. A screen reader user who activates "Go east, <reason>" on a closed exit gets the reason only as visual `Said` text, which is never announced. Their label already holds the reason, so this is low impact; `AccessibilityInfo.announceForAccessibility` would cover it.

## Over-engineering

The diagonal `ANGLE` entries are dead (S1). Nothing else to delete: `Disc`/`Line` are each used twice or more, `why` is shared by the Footer and the Map page, and there are no new dependencies.
