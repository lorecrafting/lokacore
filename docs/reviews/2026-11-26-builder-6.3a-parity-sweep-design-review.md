- Governing: [builder mode §4.3, §4.9, Appendix A](../rnd/in-game-builder-mode-2026-11-19.md), [book-ui.md Author mode](../system/book-ui.md), [catalogue, author-mode marks](../BOOK-UI-COMPONENTS.md), panel `tools/author-panel/src`.

## Findings

1. **blocker** (wrong behaviour) `mobile/app/author/build/checks.tsx:13,72`: the `/todo` row reads `<file> · N words still to write`, but `words` is the count of words already written (`kernel/ts/play/todo.ts:98`; the panel's badge says so). The author sees "212 words still to write" on a file with one blank line. Brief: show the right number under a label the owner writes (owner word item); keep the placeholder lines.
2. **should-fix** `checks.tsx:25-50`: `Nothing to check.` shows when `checks()` is empty even while `/todo` rows follow it, so the sheet says nothing is left above files still to write. Brief: the empty line only when both lists are empty. The `/todo` rows also repeat the `<key>: unwritten` rows, per file (question for the PM: keep both?).
3. **should-fix** `room.tsx:191,46-57`: the summary passes the padded `text` (`paddingHorizontal: space.md`) into `row`, which already pads and gaps. `1 exit` sits about 16 px right of the sheet's text edge (lock-light, room-night), and the dot gaps are uneven (room-light). The dot is `fg` while the summary is `dim`. Brief: `inRow` for the exits and dots, dots `dim`, no extra padding.
4. **should-fix** `kernel/ts/play/parity.json:128-131`: the `inspector-header` row is flipped to `room.tsx`, but the panel header (`right.tsx:27-66`) shows the ref, `~` count, diagnostics and "unreached from the start"; the Book summary shows none of these. The brief conflated it with §4.3's summary. Brief: add them, or leave the row `todo` (PM ruling).
5. **should-fix** `thing.tsx:55-70`: `referrers()` copies `find.ts users()`'s filter without `extends`, so it can read `· 0 referrers` on a key the server then refuses to delete; with N > 0 the act is still full action colour. One fact in two places. Brief: the count comes from the gate itself (server), and Delete is a pressable greyed row with the count as its reason while N > 0, so the refusal still names them (spec written).
6. **should-fix** `checks.tsx:66-78`: each `/todo` row is one Pressable holding the file line and every placeholder line, so at 390 px a file with many blanks is a touch target many lines tall and a scroll that starts on it opens the source. Brief: only the file line presses; placeholder lines plain under it (catalogue rule written).
7. **nit** `roomedit.tsx:133-147`: Door and Lock each show the same greyed reason (`has barrier_1` twice, lock-light). Brief: one reason, once.
8. **nit** `checks.tsx:54-63`: `/todo` is asked again on every message; the panel asks per compile. Key it to the compile.
9. **nit** `room.tsx:41-46`: `dark` and the variants open the Fields sheet at its top, not at their block (§4.3 "jumps to its block").
10. **nit** `contents.tsx:75-80`: `Go to <room>` acts sit inline among file acts; when the row wraps at 390 px, which file a Go belongs to is lost.
11. **question** card-picker and drop-step: both match the panel (`sheet.tsx:14-28` dispatches by kind; `Build.tsx:212-220` is the keep-my-place notice with `Drop it and go on`), delivered by earlier slices. Neither has a row-specific test.

Nits 7 and 8 are written as spec rules here; the spec settles them at this fix round or the next touch.

Accepted open items: the header drops the area (the `Area` field holds it); the exits word is not pressable (its rows are on the same sheet); the generated `barrier_N` key follows the `room_N` / `npc_N` precedent (the panel prompts for one).

Owner word items (placeholders, not rewritten): `1 referrers` (plural), `Delete <key> · N referrers`, `Door`, `Lock`, `has <key>`, `one-way: no way back to bar`, `dark`, `N variant(s)`, `Fields`, `Delete placement`, `Go to <room>`, the `/todo` row.

Proposed check: a test that the referrer count equals `find.ts users()` for a key named only through `extends`.

Not covered: the dark palette (both "night" shots are light), keyboard, and anything live.

Verdict: CHANGES REQUIRED (blocker 1; should-fix 2-6).
