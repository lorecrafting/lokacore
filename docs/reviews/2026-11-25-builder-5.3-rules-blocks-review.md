## Findings

1. **nit**, `kernel/ts/play/generic.ts:101`: the base `properties` now win over the if/then branch. So a zoned reaction loses the then-branch's `on: {properties: {room: false}}`. Probe: `{zone: 'z', on: {event: 'entity_entered_room'}}` offers "add room" under `on`, and the compiler refuses it. The comment "only narrows" is not true for this case. Author-side only.
2. **nit**, `kernel/ts/test/generic.test.ts:129`: the typed-first test always puts the untyped `$ref` at index 0, so the `typed > 0` mutant survives. No current schema has a typed branch first followed by an untyped one; I checked `protocol/cartridge.schema.json`. Adding one case, `[{type:'object'}, ref('Key')]`, would close it.
3. **nit**, PR body: it does not say that titles() relabels the panel's steps wait branch ("option 2" becomes "wait"). The change is intended and the kernel tests cover it.
4. **note**, `mobile/app/author/build/generic.tsx:113`: on an action whose failure does not match its check, any unrelated write adds or drops the failure outcome, including authored failure content. book-ui.md:1307 ("Not in 5.3") accepts this, and the panel behaves the same way.
5. **question**, `kernel/ts/play/card.ts` `untagged` (existing code): switching a FactValue from boolean to integer writes the old value back when the branch has no `minimum`.

No blockers. Every write path I probed lands in one /change and keeps the tag and the shared fields.
