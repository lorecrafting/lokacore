## Requirements derived before reading the diff

Spec: 07 §9; 10 §§31-32 (as amended here); 03 §§14-15; ADR-072 points 3 and 5; ADR-075 §§2-4
(S2 amendments); OFF-07; brief pins 1-6.

1. Identity and pin live in the save's one SQLite file, on its one connection (ADR-075 §2 S2
   amendment; mobile lessons).
2. The first save writes, in the same transaction as the fresh head: format version,
   lineage_id, run_id, parent null, cartridge id/version/hash, capability lock, save/IR/numeric/RNG
   versions; unknowns null (07 §9; 10 §32; AGENTS "nothing invented").
3. Open under a different content hash: typed result, nothing written, trace included (10 §32).
4. Ids from the host allocator only; scope `story/<lineage_id>/<character>` (03 §14).
5. newGame: settles a fenced attempt first; one transaction replaces head, rows, identity and
   deletes receipts; memory adopts only after commit; unknown COMMIT fences; a definite fault or
   a confirmed non-commit leaves the old save and memory and is never reported as replaced
   (10 §31 "a write failure cannot be shown as saved success"; 03 §15); the new run's trace
   opens with a header (ADR-075 §4); an old invocation id is a new attempt afterwards.
6. A corrupt or missing head is typed `save_corrupt`, the pin checked first, never replaced
   without the player (OFF-07: "does not invent state").
7. Crash recovery and receipt replay allocate no ids (10 §31: not new branches).
8. Spec amendment (spec README §11): every normative mention of bookmarks reconciled or noted.

## Checks against the list

- 1, 2, 3, 4, 7: met (`store.ts:36-49`, `authority.ts:43-103`). Pin compares content hash only;
  kernel version is rightly not pinned (ADR-075 §3 amendment: a run survives updates).
- 5: met in code; the non-commit branch is untested (F1).
- 6: met for JSON syntax; a head that parses with the wrong shape opens (F2). SQLite-level
  corruption throws (deferral, judged under F3).
- 8: met except 10 §32 (N1).
- ADR-072 point 3: `replace` is one transaction, adopt after commit. Point 5: no snapshot added.

## Findings

**F1 — blocker — `mobile/authority/local-story/saves.test.ts:276` (missing case); guards at
`mobile/authority/local-story/authority.ts:247` and `:53`.** No test injects a genuinely failed
COMMIT into a new game (storage lessons: "inject a genuinely failed COMMIT too"); the only
unknown-COMMIT test uses a lost acknowledgement of a commit that succeeded. Deleting line 247
or making the corrupt path always answer `replaced` keeps the suite green, and either would tell
the player a new game started while the old save (and, on the open path, the old world) stays:
10 §31 false success. Fix: one test where COMMIT throws without running during `newGame`,
asserting the throw, `stored()` unchanged, the same world, and the next invoke of an old
invocation id replays; one where the corrupt-path `newGame` gets an unknown COMMIT and answers
`pending`. Confirm both mutants die.

**F2 — should-fix — `mobile/authority/local-story/store.ts:92-97`.** `load` only catches
`SyntaxError`, so a head whose `rng` parses but is not an RngState (or a non-integer clock
read back from a value that parses) opens as `open`; every command then faults with
`evaluator_error` and the player is never offered `save_corrupt`. Brief pin 5: a corrupt head is
typed. Fix: check the head's rng with the existing `validate('RngState', rng)`
(`kernel/ts/src/validate.ts:51`) and return undefined on errors; head only, rows are not in
scope.

**F3 — should-fix — `docs/ROADMAP.md:68` (S6 row) and `:69` (SM row).** Deferrals recorded only
in the PR body, which is not where the next slice looks. Judgments:
- no format-version check on open, deferred to S3b: accepted, S3b row (`:65`) already owns
  unsupported-version errors;
- a file SQLite rejects (NOTADB) or a page read that raises SQLITE_CORRUPT inside `load`'s read
  (`store.ts:90` rethrows non-SyntaxError) throws instead of `save_corrupt`, and `openSmoke`
  throws at module load: accepted for S3a, but OFF-07 is S6's gate and the recovery screen is
  SM2's; name it in one of those rows;
- old-run trace entries lost when a failed catch-up precedes newGame's receipt delete
  (`authority.ts:232`): accepted (trace is derived, ADR-075 §4); name it in S6;
- if the new run's `fresh` header write fails (`authority.ts:236` leaves `behind`), the next
  `catchUp` files new-run entries under the old run's header (`trace.ts:72`, `prior` = old
  RunIds), so they carry the old `run_id`: worse than the kernel-update case the S6 row names
  (a replay of the old run would apply the new run's commands). Add it to the S6 row.

**N1 — nit — `docs/spec/10-mobile-commerce-release.md:572`.** 10 §32 still says "current
saves, bookmarks and recovery copies"; `docs/spec/IMPORT.md:118-120` lists the clauses kept
unchanged but omits this one. Add it to the retained list (vacuous like 10 §16) or note it.

**N2 — nit — `mobile/authority/local-story/smoke.ts:75`.** "across forks": no forks exist
after the owner decision; say "across new games".

## Not findings

- Tests follow AGENTS "Writing tests": literal expected values (hand-written canonical state,

## Fix round 1 (`aad22ff`, `067097e`) — verdict: APPROVE WITH NOTES

Scope: `authority.ts` newGame/settle/fence and the corrupt-save path, `store.ts` load/replace,
`trace.ts` catchUp, their callers (`openStory`, `invoke`, `adopt`), ROADMAP, IMPORT, smoke.ts
comment. Suite: 36 pass at `067097e`.

Dispositions:
- **A-F1 fixed.** A committed new game now installs a fence that adopts (`authority.ts` newGame
  fence); a failed adoption read answers `pending` and memory stays old until settled; a retry
  answers `replaced` without a second replace (fence identity check, `s.game`).
- **A-F2 fixed.** `load` treats a missing head and identity as empty only when `state_row` and
  `receipt` are empty too (`store.ts:83`).
- **A-F3 fixed.** The corrupt path calls the same `newGame` with a headless `Story`; a genuinely
  failed COMMIT throws "nothing was replaced"; a lost acknowledgement answers `pending`, then
  `replaced` on retry under the first ids.
- **A-F4 fixed.** `catchUp` writes the new run's `fresh` header before tracing its receipts under
  its own ids (`trace.ts:72-77`).
- **R-F1 fixed.** Real deferred-foreign-key COMMIT failure tests for both new-game paths.
- **R-F2 fixed.** `validate('RngState', …)` on the head (`store.ts:97`).
- **R-F3 fixed.** S6 row names NOTADB/SQLITE_CORRUPT and the lost old-run entries; SM row names
  the `openSmoke` screen; the new-run-under-old-header case is fixed in code (A-F4).
- **R-N1 accepted.** Listing 10 §32's bookmark clause as retained-vacuous in IMPORT matches the
  10 §16 treatment; no rule changes.
- **R-N2 fixed** (see N3).
