## What must be true

## Findings

- **F-1 should-fix**, `kernel/ts/src/known_answers.ts:28`. The key argument has no test, and reverting it (M3) leaves the full suite green. Failure scenario: probe world with the quest active, `attempt(w, scope, {action_key:'bram', target_ids:[ada], …})`. As shipped it answers `unsupported_capability`. With M3 it answers `not_found`, while `openStory.invoke` answers `unsupported_capability`. Then, for any cartridge with a talk alias, the known answers that Node and Hermes pin would differ from the device authority, and CI would stay green. Fix: add one row to `keyed_admission.test.ts` that calls `attempt()` with `bram` on ada and expects the literal `unsupported_capability`. This touches no frozen fixture.

No blocker. No nits.
