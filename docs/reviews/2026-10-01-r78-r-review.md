## What must be true (written from the spec before reading the diff)

From 21 §3.4, §11; 06 §14; 04 §5.2, §5.3, §5.4, §9; composition-profile.json:

1. A rule fires only from a DomainEvent or fact transition. It never fires from a wall clock. Its consequences are registered typed ops only, with no generic setter. Unknown events, ops, facts or targets fail validation in both kernels.
2. Deliveries are FIFO after their cause, with no recursion inside an op. Rules are visited in compiled stable-id order, never map or insertion order. The guard is read on the current proposal overlay, not on committed state.
3. Each delivery gets its own coordinator-assigned writer group, distinct from the root, the jobs and the other deliveries. Content never chooses it.
4. One aggregate budget covers the root and all descendants: operations, events, deliveries, reaction_depth. Exhaustion gives the fault `budget_exceeded`, and the **whole** proposal is discarded, clock and jobs included in a wait.
5. Each due job's reactions reach quiescence before the next job. Events keep their visited logical time.
6. A sequence's `fact_changed` sits at its causal position before that sequence's reactions are matched.
7. Independent writes to one fact conflict (§5.3). There is no last-writer-wins.

## Findings

**B1 (blocker): a reaction budget fault inside a job drain is untested.** Location: `kernel/ts/src/proposal.ts:223-224`.
- Mutant: `const failed = react(p); if (failed) return failed;` replaced by `react(p);`. This survives the **entire** kernel suite (248 tests green).
- Failure scenario: a cycle or deliveries overflow in a job's reactions during `wait` is dropped. The truncated chain then commits with the advanced clock and completed jobs. 04 §5.4 forbids exactly this, and the brief's acceptance asks for "Cycle → budget_exceeded, nothing commits (clock, facts, jobs unchanged)".
- The only cycle test uses a move, which has no clock and no jobs.
- Probe, run and removed: 33 chained rules with the first on entering the green, then `wait` until 20:30. At HEAD this faults `budget_exceeded` and the world is unchanged. Under the mutant it is `accepted`: the clock reaches 73800 and the truncated chain commits.
- Fix: one test in which a job's event reaches the cycle, for example a `chain(33)` world whose first link triggers on entering the green, then `wait` across 19:00. Assert `budget_exceeded` and `s.world === w`.

**N1 (nit): quest deliveries are folded into the root rather than queued.** Location: `kernel/ts/src/proposal.ts:124-125`, `world.ts:111`.
- `quest.ts deliver` runs before `propose`, so a root's quest groups (1..n) and their ops come before reactions to *earlier* root events. That is not strict FIFO (04 §5.2 step 6).
- No current root emits both a reaction trigger and `item_acquired`, so this cannot happen yet.
- Checked: `current_state` objectives are read only at `resolution` (quest.ts ~98), never in `deliver`. A reaction's fact.assign therefore cannot be missed by a state objective in the same proposal.
- The ponytail note covers only "quest deliver sees only the root's events". Slice D inherits both halves. Once a reaction can read `quest_state` after a recipe that emits a trigger and `item_acquired`, quest delivery must move into the queue.

**N2 (nit): misspelled budget keys pass silently.** Location: `kernel/ts/src/compose.ts:132`.
- `over()` takes `Record<string, number>`, and `n > LIMITS[k]!` is `false` for an unknown key.
- Failure scenario: a typo such as `reaction_dept` compiles and never faults.
- Fix: type the parameter as `Partial<Record<keyof typeof profile.limits, number>>`, or throw on a missing limit.

**Q1 (question): reaction events have no `actor_id`.** Location: `proposal.ts:197`.
- Reaction `fact_changed` events carry no `actor_id`, even when a player's move caused them. The root's own `fact_changed` does carry it.
- Intended (system-caused), or should they inherit the root actor? The schema allows either.
