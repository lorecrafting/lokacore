## Assessment

The present content-to-authority path is small and coherent for its installed subset. Content JSON cannot call arbitrary host APIs or invent mutation operators. The compiler/loader close schemas, resolve local DefinitionRefs, enforce command/event/policy/definition ownership and reject unsupported installed capabilities. The local authority retains receipt-first admission, atomic changed-row/head/receipt commits, uncertain-COMMIT fencing and post-confirmation memory adoption. The book operates through Game/GameSession plus generated contracts, with no World or Db import.

That is a good substrate, not evidence that archived catalog 21 or the upcoming M queue is already expressible. Recipes currently target one authored room detail; policies lack generic target properties/selectors; reactions hear only fact_changed and entity_entered_room and write only fact.assign; relation state is only containment; scenes are only narrate/await_ack/end. M5 dynamic death metadata and M20/M21/M22 narrative consequences need actual contract additions. None requires prebuilding the whole future catalog or replacing the installed substrate.

## New finding: ordinary FactSpec defaults cross the artifact boundary unchecked

Classification: actual static trust-boundary defect; P2 before imported/untrusted artifacts or expanded authoring/certification use. Independent audit lead separately confirmed the same source path. No runtime reproduction or test execution is claimed.

Evidence:
- protocol/fact.schema.json FactType enum and int branches validate the shape/type of default but cannot express default membership in the values array or default within dynamic minimum/maximum. Their descriptions explicitly say the compiler checks those relationships.
- lib/loka/content/compiler.ex:220-233 checks default enum membership and integer bounds, reporting FACT_DEFAULT_INVALID.
- kernel/ts/src/content/cartridge.ts:63-80 stages schema/hash/keys/time/lock/scenes/refs/installed. Reference stage cartridge_refs.ts:158-195 validates authored fact comparisons/assignments, resources, etc.; installedStage cartridge.ts:267-270 validates fact scope only. Neither checks ordinary fact defaults.
- runtime/fresh.ts:59 copies each declaration's default to factDefaults. mechanics/fact.ts:29-31 reads an unset fact from those defaults.
- mechanics/fact.ts:86-90 checks only stored state.facts, so a fresh world with an invalid default and no fact row passes that specific invariant.

Concrete regression: start from a valid artifact declaring enum values [undecided, player_led], change only its default to party_led, recompute the content hash, and present it to the loader. Static control flow admits a structurally valid ordinary FactSpec; the new world's unset fact returns party_led outside its declared values. Likewise an int minimum0/maximum10/default11 has the same gap. Schema type checks, content hashing and an empty stored-facts invariant do not establish this relationship. A content hash is an integrity digest, not author/compiler provenance.

Small repair direction for a future authorised slice: reuse the existing typed fact predicate at artifact reference validation on ordinary declared defaults, with a controlled malformed-artifact regression and literal expected diagnostic; include a real red control by removing that validation. Do not add another general guard framework or silently widen FactSpec semantics. This is not evidence of a currently malformed bundled sampler.

## What existing enforcement proves and what it does not

Inspected source:
- bin/check_all.sh:11-37 orchestrates compile/boundary/xref, generator drift, tests, Credo/size/red controls, AST tests/scan, docs validation, TypeScript checks and mobile tests. This audit executed none.
- bin/contracts.exs:94-106 requires a present differential when an Elixir host adapter is declared for a portable_capability. :205-245 generates owners/Owned unions/limits. That guards a declared adapter; it cannot detect an undeclared adapter or prove the declared differential's semantic quality.
- bin/features.exs:31-83 checks required row cells and existence of cited contracts/invariants/files/transcripts. It requires cells, not proof that a fixture exercises an invariant or semantic family. It uses implemented_in for ruleless support; does not independently derive every installed helper's full behavior.
- protocol/invariants.json declares host coordination invariants retry_replays_receipt and idempotency_payload_conflict as implemented_in none. Actual authority code enforces them; they are not portable world invariants run by that registry. Do not read none as “no host implementation”, or the broad harness statement as host coverage.
- mobile import lint closes module boundary accidents and generated-contract-only shared session imports. Rule-module lint disallows mutation/type escape/importing another rule at its rule.ts path. Shared helpers/composition root may legitimately couple to lifecycle/schedule/scene queries. These guards do not prove full “never names another mechanic” intent or protect every possible adversarial dynamic construction.
- mobile-authority-no-display-text is a string-shape heuristic with Error/module/SQL exceptions. It establishes no authority/presentation semantic purity theorem. Existing renderer code reads only projection/types and sends intents; stronger claims need review of the changed consumer.
- Observed cartridge.test.ts:29-80 uses independent fixtures/diagnostics, strict UTF-8 and predecode cap cases. The loader corpus includes ownership/key/band/attribute/slot/scene/chapter adverse cases. It has no ordinary-fact-default case. Host faults.test.ts contains real SQLite full/commit/crash paths; not mocks that merely assert a called stub. Tests were read selectively, not exhaustively surveyed or executed.

1. M5/M6: Keep planned persisted created identity/initial custody, NPC-specific HP and ownership real. Extend State/MutationTarget/DeltaOp, composition and row adoption, changed-row save/reopen and affected portable twins together under actual chosen operations. Add controlled lethal/retry/uncertain-commit/reopen cases with independently known corpse identities/custody; preserve worn/nested item roots. The first-encounter contract correctly flags this at docs/spec/conformance/first-encounter.md:46-48 and docs/system/save.md:153-155. Existing static entity maps are not sufficient.

2. M22-A before M20-A and M20/M21: Extend the shared typed consequence/event/credit vocabulary only for the actual next story consumer. If Q1/all/any/branch/kill/ring/escort scenes need resource/item/status/scene transitions, register those semantics once and route the consuming surfaces through their shared interpreter; keep selectors deterministic/bounded and credit tied to real causal events/actors. Current arbitrary story fact names remain fine, but do not use bool flags/UI observations as a second kill/ownership/escrow state machine.

3. M6 interaction: Current renderer puts non-target input-free offered actions on place buttons and target actions on item/NPC pages. During combat menus must expose real threatened-state/Stand/Flee affordances under the planned contract; “imports are clean” alone cannot guarantee escape controls. Do not add damage/death/admission logic to presenter.ts. During ordinary elapsed menus use subscribed confirmed GameView; modal scene immunity/interruption is not inferred from UI pages.

4. Future29: Persistent books/signs/houses/guilds, knowledge, ownership, transfer conservation, multi-actor social/audience and population provenance are absent semantics, not future modes of static item descriptions. Graduate a primitive at the first actual need where invariants require it. Existing portable foundation and Candidate C TS-first story rules remain the right split; no speculative Elixir story duplication, generic graph/setter, capability plug-in layer or LokaScript is needed now.

5. Authoring/certification: Resolve the ordinary-default artifact hole before broad imported content. Initial-key reachability will reject new content whose key comes through an NPC/service/quest; extend that checker only at that real route, or define a reviewed runtime-refusal disposition. The artifact4MiB cap bounds bytes but not a strict loading CPU budget: repeated alias/key/cycle scans and fixed-point reach can scale poorly in a large catalog. No performance failure measured; declare/measure the actual larger artifact before optimizing.
