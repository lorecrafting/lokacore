# Where the code and the spec disagree

For the owner. The system docs follow the code; each row is one disagreement found while
checking them at `87a1246`. Deferred requirements that an owner decision already carries are in
[future.md](future.md), not here.

| # | Spec | Code | Difference |
|---|---|---|---|
| 1 | [03 §14](../spec/03-domain-state-persistence.md) receipt fields | `mobile/authority/local-story/store.ts:23`, `:35` | The receipt has no `origin_authority_id`, `semantic_command_digest`, `result_digest` or `created_at`. A receipt whose response was altered but still validates replays as `saved`; only an invalid shape is caught (ROADMAP: carried to R12). |
| 2 | [04 §5.4](../spec/04-command-event-effect-protocol.md) advance snapshot: a cancelled or rescheduled entry is ineligible, never resurrected | `kernel/ts/src/proposal.ts:253`, `rules/schedule.ts:23` | A stale job entry is refused `invalid_state` by `run_job`, which rejects the whole advance instead of skipping the entry. No operation can make an entry stale yet (ROADMAP carry). |
| 3 | [04 §5.3](../spec/04-command-event-effect-protocol.md) "Explicit unlock-then-open may compose" | `kernel/ts/src/compose.ts:104` | Any two writer groups on one target fault `conflicting_write`; a root that activates a strict quest and then acquires its item faults (`kernel/ts/test/quest_delivery.test.ts`). ROADMAP G1: amend 04 §5.3 and compose in both kernels. |
| 4 | [04 §19](../spec/04-command-event-effect-protocol.md) and invariant `gameview_agrees_with_admission` | `kernel/ts/src/actions.ts:100`, `invariants.ts:278` | Engine verbs are listed once per verb with an always-true policy, so `open`, `unlock`, `lock`, `close` show available whatever the barrier state or key; the invariant covers `move` and `perform` only (ROADMAP Q-3: per-exit actions, a schema change). |
| 5 | [00 §4.1](../spec/00-first-cartridge-design.md) `scan` shows adjacent rooms | `kernel/ts/src/rules/movement.ts:30`, `:82` | The kernel accepts `scan` with no event; `loka play` prints `sight()`; the phone shows nothing for it (ROADMAP O-scan). |
| 6 | [10 §32](../spec/10-mobile-commerce-release.md) runs pin save, IR, numeric and RNG versions | `mobile/authority/local-story/authority.ts:148` | The pin stores `numeric_profile: null` and `rng_profile: null`; neither kernel exports a profile version. |
