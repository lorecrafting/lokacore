# Review: R4 S1 — compiled-cartridge and diagnostic contracts, owning capabilities

PR #25 (`r4-s1-artifact-contracts`), commit reviewed `7015b009c16b94d48a53ce5764ec380c79bdd6c8`.
Reviewer: independent (Fable; authored none of the work). Full review: this slice freezes an
encoding. CI green on the head (elixir, typescript, lint, android, ios).

## Verdict: CHANGES REQUIRED

Three should-fixes, all cheap now and enum/registry changes once S2 builds on them. The hash
domain, the known answer, the schema fixtures and the ownership check are sound; the
diagnostic code set has two holes and the `wait` owner contradicts the hello fixture.

## Must be true (written from the spec before the diff)

1. The hash covers only the semantic payload; the hash sits outside it; no certificate,
   signature, package or catalog field inside (05 §11, §20; CAR-10; INDEX C3).
2. Canonical bytes are unambiguous: sorted ASCII keys, no whitespace, deterministic escapes,
   non-ASCII literal, integers only (numeric-profile.md; CAR-04); a domain tag inside the payload.
3. The lock is exact; `offline_private` rejects `server_only` (05 §6; C4).
4. Definition identity is cartridge id + version + kind + key (05 §4; C1); duplicates fail (CAR-01).
5. Diagnostic shape is 08 §6; the path is a field path (CAR-02); codes are a closed set,
   one per cause; a diagnostic list has one deterministic order (Gate R4).
6. Unknown field, capability, policy op or reference fails (05 §5; A10).
7. Ownership is recorded on the registry, no second hand-written catalog (gate gap 2); the
   check fails on a missing, duplicate or unknown owner.
8. Spec notes follow README §11 and IMPORT.md's log; the 4 MiB cap lives once under `protocol/`.
9. The known answer comes from an oracle independent of both kernels, and that oracle's
   output really is loka-numeric-v1 for the values used.
10. Tests follow AGENTS.md "Writing tests".

## Checked

- **Hash domain.** `CartridgeArtifact` is `{content_hash, cartridge}` with
  `additionalProperties: false`; `cartridge.format` is the const `loka-cartridge-v1`, so its
  canonical bytes can never equal a lock (`loka-capability-lock-v1`) or an IdSource array.
  Nothing outside `cartridge` carries semantics. The manifest (compatibility requirements,
  `content_schema`, `rule_ir` pins) and the lock are inside the hash, as 05 §11 lists. Items 1–3 hold.
- **Known answer.** Recomputed independently: `json.dumps(value, sort_keys=True,
  separators=(',', ':'), ensure_ascii=False)` equals `canonical` byte for byte and
  `hashlib.sha256` of its UTF-8 gives `fe17f082…84f2`. For these values (ASCII keys, no
  control characters, one em dash, integers only) Python's rules coincide with
  numeric-profile.md (keys by code point = byte order for ASCII; `"`, `\` and controls
  escaped, everything else literal). The `value` is in authored, unsorted order, so both
  kernels' sort paths are exercised. Item 9 holds.
- **Schema mutant spot-check** (throwaway worktree, regenerated with `bin/contracts.exs`,
  both kernels' fixture tests): drop `format` from `CompiledCartridge.required` → Elixir
  fail, TS fail; drop `policies.propertyNames` → Elixir fail, TS fail. Matches the PR's sweep.
- **Ownership check broken once** (test/loka/core/registries_test.exs):
  - planted registry (movement loses `move`; calendar gains `take` and `fly`) → the main
    test fails with `[unowned: "move", two_owners: "take", unknown: "fly"]`;
  - `ownership(true, 0) -> nil` → the planted-case test fails;
  - `n <- names` (drop the unknown-name scan) → the planted-case test fails.
  Names come from `Contracts.defs()` (CommandPayload, EventPayload, Policy `oneOf`), so the
  schemas remain the only catalog; every one of the 10 commands, 8 events and 7 ops has one
  owner key. Item 7 holds.
- **Path grammar.** A compiler path starts with `[a-z0-9_]` or `"`; a loader path is empty
  or starts with `.` or `[`; a quoted member `["…"]` and an index `[n]` are distinguishable
  by the character after `[`; a quoted source is a self-delimiting JSON string. Unambiguous.
- **Order.** Path, then code, by UTF-8 bytes, then the canonical encoding of the whole
  diagnostic, duplicates removed: total and deterministic.
- **Spec notes and log.** 05 §2 and 00a §12 notes are short, dated, link the owner decision;
  IMPORT.md entry follows the existing entries. Owner decisions recorded verbatim.
- **Tests.** Expected values are the Python known answer and hand-written literals; no
  change detectors; the planted-case test is the check's red control.

## Findings

### F1 (should-fix) — the authored manifest's form is not frozen; two codes are unreachable under the only manifest schema that exists

`protocol/cartridge.schema.json:322` (DiagnosticCode description: `KERNEL_API_RANGE_INVALID:
the authored kernel_api range does not parse`, `CAPABILITY_VERSION_CONFLICT: requires names
two versions of one capability`, `UNKNOWN_CAPABILITY: requires names a key@version`).

Those causes exist only for the spec's YAML forms (`">=1.0 <2.0"`, `[movement@1, …]`). The
frozen `CartridgeManifest` (`manifest.schema.json`) has `kernel_api` as an object
`{at_least, below}` with a pattern, and `capabilities` as an object `key → version`. Under
that form a range that "does not parse" is `SCHEMA_VIOLATION` (`pattern_mismatch`), and two
versions of one capability can only be a duplicate key, which is `DUPLICATE_KEY`. The PM
decision covers policies and actions ("use the frozen AST shapes directly") but says nothing
about the manifest, and the PR freezes no source-manifest schema.

Failure scenario: S2 reads the code descriptions and implements a `>=a <b` string parser and
a `key@version` list for `cartridge.json`; the loader, the R5 fixtures and every other reader
use `CartridgeManifest` (the only schema), so a manifest authored in that form is rejected
with `SCHEMA_VIOLATION`; or S2 uses the object form, ships two dead codes, and the frozen enum
changes in the next slice.

Fix: state the authored manifest form in the `CompiledCartridge` (or `DiagnosticCode`)
description. If it is `CartridgeManifest` (recommended: nothing new to freeze), drop
`KERNEL_API_RANGE_INVALID` and `CAPABILITY_VERSION_CONFLICT` and reword `UNKNOWN_CAPABILITY`
to "a key in `requires.capabilities` is not registered at that version". If it is the string
form, S1 must freeze that source schema.

### F2 (should-fix) — no code for a `content_schema` or `rule_ir` pin the compiler or kernel does not implement

`protocol/cartridge.schema.json:322` (enum has `KERNEL_API_UNSUPPORTED` and
`CAPABILITY_NOT_INSTALLED`, nothing for the other two pins).

05 §3: published cartridges pin exact `rule_ir` and `content_schema`; "compatibility and
migrations MUST be explicit; host/app upgrades may not reinterpret old rule IR"; "do not use
one version number as a proxy for another". `CompatibilityRequirements` bounds both only by
`minimum: 1`.

Failure scenario: `cartridge.json` declares `content_schema: 7, rule_ir: 3`. The compiler,
which produces content schema 1 and rule IR 1, has no code to reject it, so it emits a
`loka-cartridge-v1` artifact whose hashed manifest claims versions the payload is not; the
loader checks `kernel_api` and the lock, has no code for these pins either, and loads it.
Adding the code later changes the frozen enum after S2 and S3 exist.

Fix: one compile-time code (for example `PINNED_VERSION_UNSUPPORTED`, data `{field, declared,
supported}`) covering both pins, and the loader stage list says whether it re-checks them
(the `format` tag already pins the artifact shape, so the loader may not need to).

### F3 (should-fix) — `wait → calendar` contradicts the hello fixture, whose lock lacks `calendar`

`protocol/capability_registry.json:224` (calendar owns `wait`); `docs/spec/00a-chapter-one-content.md:681`
("`wait` to hour 19 moves Bram through a durable scheduled command", inside §12) versus the
§12 manifest's `capabilities`, which has `schedule@1` but no `calendar`.

Failure scenario: the hello fixture (R6P's proof content) authors a `wait` action like the
`talk` action in this PR's example; `UNDECLARED_CAPABILITY` fires because its owner
`calendar` is not required; the only ways out are a 00a §12 amendment adding `calendar@1`
to a fixture the owner just froze to "only the locked parts", or changing this registry
entry after S2 depends on it.

Fix: own `wait` by `schedule` (in the hello lock; 00a §12 ties `wait` to the scheduled job it
drives; 04 §5.4 describes the advance as draining due jobs), or amend 00a §12 now. PM's call;
the PR body's alternative "a foundation time rule, not a capability" is not expressible in
the check as built.

### N1 (nit) — three hand-copied DefinitionRefString patterns with no drift guard

`protocol/cartridge.schema.json:20,29,38`. The validator subset allows only `{"pattern"}`
under `propertyNames` (`lib/loka/core/contracts/schema.ex:120`), so the copy is forced, but
a later amendment of `identity.schema.json#/$defs/DefinitionRefString` (say the 64-character
lookahead) would leave these three behind silently. One assertion in `contracts_test.exs`
that each equals the identity pattern with `[a-z][a-z0-9_]{0,63}/` replaced by `<kind>/`
closes it.

### N2 (nit) — 00a §12 note overstates 05 §3

`docs/spec/00a-chapter-one-content.md:521`: "its manifest gains the `title` 05 §3 requires".
05 §3's text only shows `title` in an example; the requirement is `CartridgeManifest`'s
`required` (R3 PR 4a). Cite the schema.

## Notes (no action required)

- Diagnostic order is "comparing UTF-8 bytes". JavaScript's default string ordering is by
  UTF-16 code unit, which differs for a BMP character above U+D7FF against an astral one;
  S3 must compare bytes (`Buffer.compare`), not `<`. The contract is right as written.
- The `UNDECLARED_CAPABILITY` example path `facts.facts["village.arrived"]` implies a
  collection file `facts.json`; the JSON source layout is S2's to fix, but the S2 brief should
  name it so this example does not become the de-facto layout by accident.
- `INVALID_JSON` names two decoders (source `JSON`, artifact canonical parser); one cause
  class ("the required decoder rejects the bytes"), acceptable.
- PM decisions challenged: none. Omitting assets/localization behind the format tag, lock =
  declared capabilities, dropping the >64-after-mapping code (mapping preserves length, the
  64 limit is a `SCHEMA_VIOLATION`), and dialogue owning the choice commands/events with the
  04 §5 note are all sound. Of the ten unnamed owners only `wait` (F3) costs later work.
- Over-engineering: nothing to cut. `ArtifactSize` as a one-number schema def is the
  smallest placement that reaches both kernels through the existing generator.
