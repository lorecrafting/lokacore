## Selected implementation policy, adopted for source assignment after dependency merges

Choose **explicit Begin epilogue at the Green**. Merely legal entry, rendering, elapsed settlement, reopen, death respawn or resolving the second quest never starts it. This handles players already at Green without forced leave/re-entry and supplies a clear player intent. Add an inspectable, non-readable `market_cross` detail to the existing Green room, where the room text already describes it. The five recipes target that detail and the current recipe projection offers the eligible one as an ordinary World action; no targetless recipe contract or generic action change is needed. Use existing GameSession routing, only with actor-owned Q2 terminal rescued/stays or failed/lost, Q3 resolved/prior or fox, their matching bell scene ended, no running scene/combat/pending choice, and epilogue not started/completed. All five legal pair predicates are mutually exclusive; lost×fox is impossible/refused.

Pending/armed finale is **derived from these durable immutable terminals and acknowledged bell end**, with unseen epilogue state. Do not add an armed flag/job/queue if the predicate preserves the required once-only state. Never require S1 or another side quest. Ordinary movement/corpse recovery remains available while eligible. No screen callback writes gameplay state.

Reuse A1/A2's static modal scene mechanism. Author five small pair-specific Begin recipes (one visible label, one current eligible action) and five three-line scenes; their exact action identities bind the pair at start. Extend scene start hook only with exact accepted `action_completed` trigger matching recipe, actor and `market_cross` subject at Green; scene definition validates that source action/detail and its once-only eligibility. Do not infer Begin from movement or custom display events. This static content avoids a new narrative template/variant engine. After start, selected scene identity freezes the ending; text cannot switch on a subsequent render.

Continue must carry the **drawn scene identity and shown line**. A freshly minted id with stale identity/index refuses unchanged; exact invocation/command replay retains receipt semantics before stale-state admission. Shared ActionSet, direct-command admission, Scene rule and Book freshness agree. Advance the current API and generated schema/action input contracts to one closed bound Continue shape; retire obsolete development-only empty-input compatibility as permitted by the [forward-development decision](../../decisions/owner-decision-forward-development-2026-10-05.md). Independently re-pin the new current fixtures, preserve current-behavior checks and explicit old-release refusal. Scope includes all actual direct callers of Continue.

Acknowledged scene end owns an explicit **bounded terminal consequence**: three declared player memory fact assignments and one typed story-point reach. Lower with existing fact.assign deltas, shared conflict/query/output budgets and one writer per target; no generic consequence/script grammar. Store prologue completion as an **engine-managed reserved player fact marker with declared outcome**, only the story-point producer writes it. Compiler synthesizes/validates its FactSpec and reserves its namespace, as for scene facts; no new foundation delta/state table is needed. Chapter projection uses that marker for scene-end-triggered points while preserving current dialogue-trigger derivation. StoryPointDefinition accepts the narrow exact scene-end trigger; validate references, unique trigger ownership, marker vocabulary and capability/API gating in both compiler and loader. No fabricated quest-resolution dialogue or credits-screen report.

Emit one typed story_point_reached from acknowledged final end; authority's existing delivery.reached and commit path writes a pending report with memories, scene end, marker and receipt in **one transaction**, then adopts disk, then confirms UI. Report remains local/pending when offline; no submit/account/network feature is added. Keep any report already legitimately present on replay rather than allocating another. Reuse receipt/reconciliation and reserve marker semantics rather than deriving completion from a later report's delivery status.
