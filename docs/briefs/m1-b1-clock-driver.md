## Goal and adopted-policy inputs

Make a real local headless authority/session account elapsed time once, settle recurring due boundaries without skipping, reserve one current player input behind a finite horizon, and replay actual committed elapsed traces through the trusted entry. Existing PM policy supplies rate50, monotonic active time, wall resume/rollback rebase, 16 commits per host turn, receipts before freshness within a matched durable run and authority-only elapsed. Do not change A identity semantics, World hashes, resource/calendar algebra or player admission to achieve it.

## Small host-only durable checkpoint

The PM adopts a STRICT singleton `elapsed` row beside save/head: durable run, accounted wall milliseconds, remainder and fixed target. Rate stays in the pinned cartridge; debt is `target - head.clock`, not another stored counter. Remainder is [0,999]. For elapsed integer milliseconds d, calculate `total = old remainder + d × rate`, `target = old target + floor(total / 1000)`, remainder modulo1000. Use the PM-approved exact checked Number base1000 decomposition for intermediates, validating nonnegative terms/sums and the resulting target as safe integers. This preserves the full accepted safe target range without BigInt, dependencies or a numeric-profile amendment. Retain debt; never base a newly sampled target on lagging head.

Load validates run, finite safe nonnegative wall/target, target at least confirmed head and remainder. Capture one target and candidate checkpoint, then commit successive segments through earliest pending due boundaries to that target. One accepted segment writes checkpoint plus normal head/changed rows/receipt in the same existing transaction. Adopt confirmed state only; unknown COMMIT fences both elapsed and input, and reconciliation reloads checkpoint as well as world/revision. Failed attempts retry the same candidate without fresh sampling. A deterministic kernel fault retains debt and surfaces recovery, never skips a job.

Necessary administrative case: initialization, fractional account and negative-wall rebase may produce no positive logical advance. A narrow durable-run-guarded metadata transaction writes checkpoint (and format on upgrade) without gameplay receipt/revision/trace; never call A with an empty interval. Reuse transaction/reconcile rather than creating another store. Compare the durable run plus exact prior/candidate row only after rollback closes the transaction: candidate means confirmed account, prior means failed account eligible for retry, unexpected state is honest corruption/recovery. Before adoption preserve the existing gameplay fence. No checkpoint transaction may accidentally roll back another unknown gameplay transaction through store.transaction's convenience rollback.

Adopted compatibility: elapsed saves use `loka-save-v2`, legacy play-time stays v1. A v2 elapsed save missing its row is corrupt. Only a v1 save already pinned to the same elapsed-capable release may initialize v2 at its current clock in one rollback-safe administrative transaction, without credit before upgrade. Do not retarget a pin or clone old releases. If no prior pinned release is bundled, keep existing pinned_release_missing/explicit Start over; preserve owner save. The governing adoption is [B1 durable elapsed policy](../decisions/pm-decision-m1-b1-durable-elapsed-2026-10-04.md).

## Driver and reserved invocation

Use a small local-story driver with actual controlled headless session use. A session driving an elapsed profile requires actual wall/monotonic sampling functions (controlled in headless use); missing functions fail honestly rather than silently freezing time or repurposing latency. A direct pure/authority elapsed test still uses A's explicit target entry without a host driver. Sampling functions are separate from latency; active monotonic timestamps use floored absolute integer milliseconds. Persist wall at confirmed accounting, keep monotonic baseline only in memory. Resume wall delta is max(0,new-old); a negative gap still persists the new lower anchor without clearing debt/remainder. Never call a background/network service or deep-copy state.

Each fixed horizon settles to min(target, earliest pending due after current clock), preserving existing equal-time job ordering. Commit at most16 segments per host turn, then yield with durable debt. An already-due job at/before current clock or need to change proposal cancellation is a PM/spec trigger, not a zero-length loop. The callback captures expected durable run; Start over/replacement invalidates it before receipt access. Continuation close already ignores departed NPC presence on committed main65ce (see ../system/book-ui.md#npc-dialogue-and-action-details); B1 must preserve that existing admission, not add a bypass. B2 owns the real lifecycle timer chain; B1 consumes the driver through a real headless session, not an unused timer interface.

New input: settle fences; identify and replay a known matching receipt before sampling; reject already stale input; privately reserve its original identified intent/digest/run. Capture one prerequisite horizon, settle existing debt then that finite horizon, and semantically resolve the same targets against the settled world. Do not recheck the original token against its own elapsed revisions. This exemption exists only inside the authority's successfully preflighted reservation, never a caller ignoreFreshness flag or forged latest token. Different intent conflicts; the same retry retains the reservation; replacement cancels it. No durable player command queue. Later time cannot extend/starve its captured horizon.

Extend the shared session narrowly: one catching_up reply distinct from unknown-save pending, one existing stable pending invocation identity and a narrow GameSubscription with **state** (confirmed view plus elapsed/catch-up/save status) or **completion** (the one terminal reserved attempt), using existing Game/attempt identity. Immediate replies are never also emitted as completion. Reserve completion context before mutable redraw; B2 must receive enough identity/prior projection to route the actual action exactly once. The one pending attempt stays in session until terminal completion/confirmed failure, including storage reconciliation. Ordinary immediate terminal calls stay synchronous. Renderer receives no World/Db or elapsed entry.

## Real trace replay

Local trace headers already use SaveMeta.run_id through save.ids → authority.traceAfter → trace.catchUp; player invocation scope remains story/lineage/character. No Game.trace API exists. B1 captures actual trace rows through the existing storage harness/export boundary, never invents a product API for a test.

Preflight the supported fresh single-header segment before execution; capped prefixes/nonfresh or fault-rich segments retain their existing limits. For an elapsed-bearing segment, bind semantic save run from the recorded header, validate every record's run and elapsed payload run before trusted dispatch, then use A's frozen actor/world/ID/from/until validation. Ordinary commands keep the player step. Never infer run from the first payload, allocate a new CLI run, sample wall time or use measured=false as permission. Clarify observation ReplayIds prose: local durable save run versus independent CLI/simulator execution run; no new trace field is needed for supported producers. Retain byte-identical checking and derived trace recovery. Test a fresh committed local trace with elapsed followed by an ordinary command; do not claim capped/nonfresh/fault-rich segments suddenly reconstruct a fresh world.
