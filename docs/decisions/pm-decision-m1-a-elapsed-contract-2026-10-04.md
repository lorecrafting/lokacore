# PM decision: M1-A elapsed authority contract — 2026-10-04

Under the [owner delegation](owner-decision-autonomous-mechanics-2026-10-03.md) and [adopted mechanics plan](pm-decision-mechanics-continuation-plan-2026-10-03.md), the PM selects this additive M1-A contract. These are PM choices, not exact owner preferences.

- `manifest.time_policy = {profile: "real_elapsed", rate: positive safe integer}` opts into elapsed logical seconds per real second. Absence retains frozen legacy `play_time`. An elapsed manifest requires kernel API `at_least >= 1.1` and `schedule@1`; the installed kernel API becomes 1.1. Existing fixture locks, durations and hashes stay unchanged.
- Schedule owns authority-only `elapsed {actor_id, run_id, from, until}`. Its CommandId is UUIDv8 over canonical `["loka-elapsed-command-v1", run_id, world_context_id, from, until]`, using the existing IdSource SHA-256/version/variant algorithm. `run_id` is durable save identity, never session or physical authority placement. No World field is added.
- Only the narrow pure `stepElapsed` entry accepts elapsed. Normal `step`, invocations, actions and aliases cannot admit it. The entry validates the command and its derived identity, actor/world, opted-in policy, ownership and existing proposal budgets. It requires `from == clock` and `until > from`, produces existing `time.advance`, no own event/RNG, and retains due-job order and atomic faults. Its outcome is `elapsed`.
- The local authority's trusted `elapsed({expected_run_id, from, until})` checks current durable run before any receipt lookup; a mismatch is `stale_view` with no receipt/state change. Within that run, a matching persisted elapsed receipt replays before checking the current clock, returning the first result byte-for-byte. The domain CommandId also serves as the receipt invocation key; elapsed intent uses the separate `loka-elapsed-intent-v1` digest/version over its full Command. Existing commit/adopt/fence machinery remains.
- Elapsed profiles advertise/admit no Wait, including custom actions resolving to Wait. Compiler and loader reject authority elapsed actions and elapsed-profile Wait actions; elapsed-profile recipes reject an authored nonzero duration. Absence of duration means zero; legacy durations are unchanged. Scene player actions remain Continue-only while elapsed time proceeds through its independent trusted entry.

M1-A establishes the checked profile and authority receipt seam. M1-B supplies clock conversion, integer millisecond remainder, anchors/debt, lifecycle, chronological catch-up and sampler content. Conversion uses 1000 milliseconds per real second, checked arithmetic and retained remainder; no silent absence cap. No M1-A timer, elapsed sampler, UI or old-save reset is delivered.

M1-A proves persisted elapsed replay directly through the trusted authority/pure entry. The paused `loka play --replay` reader still uses default player admission; its authority-command dispatch and trace run-namespace verification are an explicit M1-B first elapsed trace-consumer carry, before full driver/trace conformance is claimed. No CLI gameplay/alias work is resumed here.
