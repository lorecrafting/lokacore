## Account, run and admission contracts (`protocol/account.schema.json`)

Account/run binding, Story milestone reports and acceptances, and Realm admission (23 §2-§7, §11; 03 §25-§27). Host and platform records, never portable gameplay inputs: no StateScope here, and none of this enters the canonical gameplay hash (03 §26; 23 §2).

- **AccountId**: A platform account (23 §2, §5): server-owned, never reused. Lowercase hyphenated UUID, any version.
- **AdmissionPolicy**: A deployment's versioned admission policy (23 §5, §7): a conjunction of requirements, at least one. Ungated is its own explicit kind, never an empty list.
  - `gated`: Every requirement must be met.
  - `ungated`: Intentionally no requirement.
- **AdmissionRequirement**: A requirement and its explicit alternative qualifying milestones, at least one (23 §7).
- **AdmissionResult**: A server admission decision (23 §7): eligible, or the missing requirements, with the policy and progress versions it was evaluated at.
  - `eligible`
  - `missing_requirements`
- **EvidenceClass**: How a milestone was evidenced (23 §6). A client cannot select or upgrade it.
- **LocalProfileId**: A local profile on a device (23 §2), distinct from AccountId and CharacterId. Lowercase hyphenated UUID, any version.
- **MilestoneAcceptance**: The platform's durable acceptance record (23 §5 'Platform acceptance'): authenticated account, canonical payload digest (hash of the MilestoneReport), recognized release and milestone, evidence class, acceptance-policy revision and result. integrity_conflict: the report id was reused with a different payload; outcome_conflict: another outcome for the same milestone in the same run (23 §5). The server receipt time is host metadata whose format is fixed with the platform API (R12A).
- **MilestoneReport**: The payload of one milestone report (23 §5 'Local milestone/report'): milestone key, occurrence id, run and exact release, outcome and the observed game revision. It names no account (authentication supplies it) and no evidence class (only the server assigns one, 23 §6).
- **MilestoneReportId**: One milestone occurrence's report, stable across retry and restore (23 §4, §11). Lowercase hyphenated UUID, any version.
- **QualifyingMilestone**: One approved (release hash, milestone, outcome) that satisfies a requirement (23 §7).
- **QueuedReport**: A report in the local queue (23 §4, §5): account_id is the binding recorded when queued, verified on upload and never rebound to another account (absent for an unbound guest run).
- **ReportDisposition**: A queued report's delivery state (23 §4). A report is never dropped after a retry limit.
- **RequirementId**: A stable admission requirement id, namespace.name@version (23 §7: onboarding.loka_fundamentals@1); each segment lowercase snake_case, at most 64 characters.
- **StoryRun**: A Story run and its binding (23 §5, §11; 03 §25): the exact cartridge release, the local profile, and the account once bound (host-side, outside portable semantics, 23 §4). parent_run_id is the run a restore or fork branched from; alone it is not full restore provenance: the parent snapshot/ancestor revision (23 §11; 03 §25) belongs to the R6 save-header contract. The server enforces that an account binding and release never change after registration (23 §5).
- **StoryRunId**: A Story run/save lineage (23 §5; 03 §25). A semantic restore or fork is a new run (23 §11). Lowercase hyphenated UUID, any version.

## Action contracts (`protocol/action.schema.json`)

Action definitions, ActionInvocation, TargetSpec and TargetResolution (04 §1, §2, §18, §19; 06 §20; 21 §7).

- **ActionDefinition**: An advertised affordance (04 §19; 06 §20; 21 §7): stable key, localization label, target spec, the portable Command type it resolves to (checked against the command registry when content compiles), presentation priority, required input parameters, policy and accessibility description. Aliases, costs and cooldown hints arrive with the text parser and cost capabilities.
- **ActionInput**: The validated input of an ActionInvocation (04 §1). Closed: each field is a registered input parameter, and the ActionDefinition's `input` lists which ones the action requires (06 §20). The parameters are those the R6P proof uses (pre-release-proof.md).
- **ActionInputParameter**: An input parameter an action requires (06 §20), one of the ActionInput fields.
- **ActionInvocation**: A host-neutral gameplay intent from an advertised GameView action; not yet an authoritative Command (04 §1, §2). invocation_id is the stable retry identity (03 §14). target_ids is ordered and its order is semantic (03 §14, invocation-intent digest). view_freshness_token is opaque admission metadata, not intent (04 §16). The 8-target and 128-character caps are admission limits of this contract version (not spec numbers); changing them is a contract version change.
- **Key**: A stable semantic key: lowercase snake_case of at most 64 characters, the DefinitionRef segment rule (03 §2). Used for action keys, directions, choices, outcomes and key-valued facts.
- **TargetResolution**: The deterministic result of resolving a target (14 §R3A; 21 §7: none | unique(target) | ambiguous(candidates), no random tie-breaking; 04 §18: ambiguous search returns structured candidates). candidate_ids are 2 to 1024 distinct EntityIds (1024 is the composition profile's selector_cardinality) in ascending code-point order of the id string (owner decision: docs/decisions/owner-decisions-r3-open-questions-2026-09-24.md, item 1). The subset cannot express order or distinctness, so invariant target_candidates_ordered in protocol/invariants.json carries it.
  - `none`: No candidate matched.
  - `unique`: Exactly one candidate.
  - `ambiguous`: Two or more candidates.
- **TargetSpec**: The candidate scopes an action's target is resolved from (21 §7): the scopes the R6P proof resolves to an EntityId. equipped, connections, inspectable_details, party and privileged global scope are added with their first use, with a target identity for non-entity targets (21 §6). Accepted kinds and capabilities are added with the capability registry.
  - `none`: The action takes no target.
  - `entity`: One entity from the listed scopes.

## Capability contracts (`protocol/capability.schema.json`)

The capability registry vocabulary, exact capability versions and the capability lock (05 §3, §6, §11; 09 §21). The registry itself is protocol/capability_registry.json.

- **CapabilityKey**: A capability key (05 §6), lowercase snake_case, at most 64 characters. A capability contract is key@version.
- **CapabilityLock**: The exact capability lock of a compiled cartridge or deployment (05 §3 'Compatibility versions', §6, §11): every capability version it executes. capability_lock_hash (09 §21) is hash(lock) under loka-numeric-v1; format is the hash domain tag, and any change to this format takes a new tag. Resolving a manifest's requirements and registry dependencies into a lock is the compiler's job (R4).
- **CapabilitySpec**: One registry entry (05 §6): a capability version, its portability, and its semantic residency from the residency matrix (05 §6 'Capability semantic residency matrix'). Portability limits residency (this table is the PM's adopted reading of 05 §6, not spec text): a portable capability is a portable semantic foundation or portable capability implementation, server_only is a Realm-only semantic capability, client_presentation_only is client presentation; authority-host coordination and authoring/certification are never capabilities (05 §6). A null residency is not yet classified. An Effect names the capabilities that may emit it (allowed_origins in protocol/effect_registry.json). A capability lists the commands, events and policy ops it owns (05 §6: a capability owns the commands, events and policies it introduces); each registered one has exactly one owning capability key, checked in test/loka/core/registries_test.exs. 04 §5 routes a choice to the capability that opened it; single static ownership is revisited when scene/quest choices arrive (R7). Only the portable branch has these fields for now; a server_only capability gains them with the first command, event or op it owns.
  - `portable`: Runs on every host, Story and Realm (05 §6).
  - `server_only`: Realm-only; an offline_private cartridge cannot depend on it for gameplay (05 §6).
  - `client_presentation_only`: Presentation only, never gameplay legality or authoritative mutation (05 §6).
- **CapabilityVersion**: A capability contract version (05 §6): a positive integer. key@version is immutable in meaning once published; a breaking change takes a new version (05 §6, 'Capability version immutability').
- **CapabilityVersions**: Exact capability pins, capability key to version (05 §3 requires.capabilities; 05 §6). A map, so one version per key: the canonical decoder rejects a repeated key, and canonical encoding sorts keys.
- **ResidencyClass**: The six responsibility classes of the 05 §6 residency view ('Capability semantic residency matrix'). A capability's residency is one of the other four (CapabilitySpec); authority-host coordination and authoring/certification are never capabilities and appear only as Responsibility rows.
- **Responsibility**: A row of the 05 §6 residency view that is not a registered capability (protocol/residency.json): a portable semantic foundation contract that both kernels must implement with golden cross-host parity, or a host or authoring responsibility named in 05 §6's 'Owns' column. fixtures lists the conformance files both kernels are tested against; an empty list means none is bound yet, never that none is needed. Host services are not made into gameplay capabilities by appearing here (05 §6).

## Cartridge artifact contracts (`protocol/cartridge.schema.json`)

The compiled cartridge, its artifact file and the compiler and loader diagnostics (05 §8, §11, §12, §20; 08 §6; 14 §R4). R4 minimal: the frozen kinds only; rooms, NPCs, schedules, quests, dialogue, assets and localization join with their features, under a new format tag.

- **ArtifactSize**: The byte length of a cartridge artifact file, checked before decoding: at most 4 MiB (owner decision, docs/decisions/owner-decisions-r4-2026-09-25.md, item 2). bin/contracts.exs emits the maximum into kernel/ts/src/contracts.gen.ts as ARTIFACT_MAX_BYTES; Elixir reads it here.
- **CartridgeArtifact**: The compiled artifact file: one canonical JSON document, built and never committed (05 §20). content_hash is the cartridge hash (CartridgeRelease.cartridge_hash): SHA-256 of the canonical bytes (loka-numeric-v1) of cartridge. It hashes cartridge only, never itself, so it can sit beside it (CAR-10); the loader recomputes it and rejects a mismatch.
- **CompiledCartridge**: The semantic payload a cartridge hash covers (05 §11 'Hash domains and attestations'): the manifest with its compatibility requirements, the exact capability lock (exactly requires.capabilities until a registry dependency exists; the loader rejects a difference with LOCK_MANIFEST_MISMATCH), and the normalized definitions of the frozen kinds, each map keyed by DefinitionRefString so canonical key order orders it. A key's cartridge_id and cartridge_version are the manifest's id and version and its last segment is the definition's key; the compiler guarantees this and the loader rejects a mismatch (ARTIFACT_DEFINITION_KEY_MISMATCH); the subset cannot express it. format is the hash domain tag and selects the variant. Compatibility (PM ruling, R5 S1 review A7/F3): adding an OPTIONAL field to an existing definition kind, or an optional new definition map, keeps the tag, because an artifact without it keeps its bytes, hash and meaning; a change in the meaning or requirement of an existing field (a field made required, removed or reinterpreted) takes a new tag. Loaders stay fail-closed: an older loader rejects a field it does not know as UNKNOWN_FIELD, and kernel_api ranges govern which loader a cartridge needs. No certificate, signature, package or catalog field belongs here (CAR-10). In R4 the authored cartridge.json is exactly the CartridgeManifest object form (kernel_api as {at_least, below}, capabilities as key to version); the string forms (">=1.3 <2.0", key@version) are not accepted yet.
  - `loka-cartridge-v1`: loka-cartridge-v1 (R4): the frozen kinds of R4 only.
  - `loka-cartridge-v2`: loka-cartridge-v2 (R5 slice 1): v1 plus rooms, the entry room and the default-locale text catalog. The compiler emits v2 exactly when the source has rooms, an entry or a text catalog, so a cartridge without rooms keeps its v1 bytes and hash.
- **Diagnostic**: A structured diagnostic (08 §6; 05 §8: every compile stage emits them). message_key is diagnostics. followed by the code in lowercase; data carries the code's facts as strings and integers; suggested_capabilities lists capability pins that would fix it (the key@version form requires uses), possibly none. A list of diagnostics is in one deterministic order (05 §8, CAR-04): by path, then code, comparing UTF-8 bytes, then by the canonical encoding of the whole diagnostic; an identical diagnostic appears once.
- **DiagnosticCode**: A diagnostic code: a closed set, one code per distinct cause (08 §6: repair loops read codes and data, never prose). INVALID_JSON: a source file is not JSON (RFC 8259, UTF-8); in the loader, the artifact is not UTF-8 or fails the canonical decoder (loka-numeric-v1), duplicate keys included, path empty, data {}; DUPLICATE_KEY: an object in a source file repeats a key (Elixir's JSON keeps the first silently, so the compiler checks it); UNKNOWN_FIELD: a field outside the registered schema (05 §5); the validator's unknown_property; in the loader, path the validator's, data {}; SCHEMA_VIOLATION: any other schema error; data.error is its ErrorCode (error_registry.json); a v2 source (rooms, an entry or text.json) without an entry is missing_property at cartridge.entry; in the loader, path the validator's; MISSING_MANIFEST: the cartridge has no cartridge.json (05 §3); path is cartridge; DUPLICATE_DEFINITION: two definitions in one cartridge have one DefinitionRef (03 §2, 05 §4; other cartridges' refs differ, CAR-01); FACT_NAME_COLLISION: two authored fact names map to one key after each . becomes _ (owner decision, IMPORT.md); ## Command contracts (`protocol/command.schema.json`)

The portable semantic Command registry (04 §1, §3, §21; 14 §R3A). Host-only CommandContext (session, receipt time) is not part of it.

- **Command**: A semantic Command (04 §3): the portable, replayable input. id is derived from the idempotency scope and the InvocationId (IdSource command_id; owner decision, docs/decisions/owner-decisions-r3-lanes-2026-09-24.md), never from authority placement. That derivation is for invocation-derived commands only; an authority-internal command (run_job) derives its id under a different IdSource tag over its own identity (job id and occurrence), defined where run_job first executes, so a client invocation id can never land on a job's receipt. Every host serializes an equivalent command to the same canonical bytes (04 §21).
- **CommandPayload**: The registered Command types; an unknown type fails before game rules (04 §3). Invocation-derived types carry the actor; run_job is authority-internal (04 §1) and is never built from a client invocation. These are the types the R6P proof uses (pre-release-proof.md).
  - `move`: Move through a connection.
  - `look`: Observe the current place, or, with target_id, one thing in it: an id the authority's target resolution returned as unique (21 §7; 04 §17, §18), never the player's words.
  - `take`: Take an item into the actor's inventory.
  - `drop`: Drop a held item into the current place.
  - `talk`: Talk to a character.
  - `accept_quest`: Activate an offered quest.
  - `choose`: Resolve a pending choice.
  - `close_choice`: Close a pending choice without choosing.
  - `wait`: Advance logical time to `until`.
  - `run_job`: Execute a due scheduled job (authority-internal).
- **LogicalTime**: Explicit logical time (01 A6; 04 §4). Units are fixed by the world calendar, not here.

## Decision contracts (`protocol/decision.schema.json`)

The decision result (04 §5, §5.0, §5.2).

- **DecisionResult**: What a pure decision returns (04 §5). accepted: a provisional proposal (delta, proposed events, effects, next RNG) with a typed outcome, including an admitted attempt that failed in game terms (04 §5.0). rejected: not admitted; consumes no RNG, time or cost (04 §5.0). fault: budget, conflict or evaluator fault; the whole proposal is discarded, so it carries none (04 §5.2 step 7). narration, when the attempt has any, is the required narration the host commits with the result and the receipt replays (04 §5.2 step 7; 06 §43); absent means none. Its 64-line cap is an admission limit of this contract version, not a spec number; output_bytes in the composition profile bounds the whole result. Projection hints arrive with GameView.
  - `accepted`: An admitted attempt.
  - `rejected`: Not admitted.
  - `fault`: Discarded whole.
- **RngState**: The four-word gameplay RNG state (numeric profile): integers in 0..2^32-1, not all zero.

## StateDelta contracts (`protocol/delta.schema.json`)

The StateDelta algebra: typed operations, their mutation targets and preconditions (04 §1, §5.1, §5.3; 14 §R3A). Composition (overlay, conflicts, invariant checks) is kernel behavior with known answers in protocol/fixtures/composition.json.

- **ContinuationId**: A pending choice/continuation (04 §5.3 'Choice/continuation resolution'), created from IdSource. Lowercase hyphenated UUID, any version.
- **DeltaOp**: One registered delta operation (04 §5.3 families). Each description names the op's target and precondition. Resource adjustment arrives with the resource capability.
  - `fact.assign`: Target: fact (fact, scope, subject_id). Precondition: current value equals `expected` (the fact's default if unset).
  - `entity.transfer`: Conserved transfer. Target: containment (entity_id). Preconditions: the entity is in source_id; destination_id is not the entity or inside it; destination capacity holds (03 §23: one container per entity).
  - `quest.activate`: Create a QuestInstance in state active. Target: quest (instance_id). Precondition: no instance of the quest is active or objectives_complete in the scope.
  - `quest.transition`: Target: quest (instance_id). Preconditions: current state is `from`; from -> to is a legal 06 §1 transition; `outcome` is present exactly when `to` is resolved or failed with an outcome.
  - `choice.open`: Open a durable continuation (04 §5.3 'Choice/continuation resolution') with everything needed to resume it after a restart: the character who may choose, the owning definition and beat, the bound roles and the offered choices. Target: choice (continuation_id). Precondition: the continuation does not exist.
  - `choice.resolve`: Target: choice (continuation_id). Preconditions: the continuation is pending, offers choice_id, and opened at committed revision expected_revision (04 §5.3 'expected revision').
  - `choice.close`: Target: choice (continuation_id). Precondition: the continuation is pending.
  - `job.schedule`: Target: job (job_id). Preconditions: the job does not exist; due_time is strictly later than the current logical time, and during an explicit advance later than its target (04 §5.4).
  - `job.complete`: Consume a due job occurrence when its run_job commits, so it is never selected again (04 §5.4). Target: job (job_id). Preconditions: the job is pending and its due_time is not later than the visited logical time (the clock at ordinary admission, or the job's visited due time during an explicit advance; 04 §5.4). It is proposed only by the job's own run_job at its visited due time.
  - `time.advance`: Target: clock. Preconditions: current logical time equals `from`; `to` is later than `from` (04 §5.4).
- **FactValue**: The value of a fact, in fact.assign, fact_compare and fact_changed: a Key, a safe integer or a boolean, the value types FactSpec declares (fact.schema.json; 03 §7). Which one a fact takes is its FactType, which the compiler checks.
- **JobId**: A same-authority scheduled job (03 §13; 04 §5.4), created from IdSource. Lowercase hyphenated UUID, any version.
- **MutationTarget**: Canonical mutation-target identity (04 §5.1): two ops conflict when their targets are equal as canonical JSON and they come from different writer groups without a registered composition rule. Also the target a conflict fault reports (04 §5.5).
  - `fact`: A scoped fact.
  - `containment`: An entity's one container.
  - `quest`: A QuestInstance's lifecycle.
  - `choice`: A continuation.
  - `job`: A scheduled job.
  - `clock`: The logical clock.
- **QuestInstanceId**: A QuestInstance (03 §12; 06 §1), created at activation from IdSource. Lowercase hyphenated UUID, any version.
- **RoleBinding**: One role a continuation bound when it opened (04 §5.3 'bound roles'), for example the NPC the choice is made with.
- **StateDelta**: A non-committed proposal of authoritative changes (04 §1). ops are in semantic order: the root's explicit sequence, then deliveries in FIFO/registry order (04 §5.2); never map, file or arrival order. Each op names its mutation target (MutationTarget) and its precondition, checked against the proposal overlay of the ops before it; a failed precondition or two writer groups writing one target without a registered composition rule faults the whole decision (04 §5.1). There is no last-writer-wins. Canonical serialization is the canonical JSON of this value (numeric profile). Its size is bounded by the composition profile's operation budget, not by this schema.
- **WriterGroup**: Coordinator-assigned writer-group identity of one explicit sequence (04 §5.3): the root sequence or one reaction delivery. Content never chooses it.

## Effect contracts (`protocol/effect.schema.json`)

Effects and the effect registry's durability and idempotency classifications (04 §1, §10, §11; 03 §16; 14 §R3A). Same-authority changes are StateDelta, never Effects.

- **Effect**: An instruction produced by a decision, applied only after commit (04 §1, §10). Its type's classification is in protocol/effect_registry.json.
- **EffectId**: An Effect; also its idempotency identity at the receiver (04 §10), created from IdSource. Lowercase hyphenated UUID, any version.
- **EffectPayload**: The registered effect types (04 §10): the two ephemeral post-commit effects 04 §1 names that the R6P proof needs. Durable types arrive with their first cross-authority use.
  - `client_notification`: An ephemeral notification to one character.
  - `scheduler_wake`: Wake the scheduler after a job was committed.
- **EffectRegistryEntry**: One entry of protocol/effect_registry.json: an effect type's classification (04 §10). Durable effects use the outbox, at-least-once with idempotent application (never 'exactly once'), always require an idempotency identity, retry until a terminal disposition and declare their reconciliation. Ephemeral effects run after commit and may be dropped or reconstructed.
  - `durable`: Crosses a boundary that cannot commit atomically (outbox).
  - `ephemeral`: Post-commit presentation or notification.

## Error contracts (`protocol/error.schema.json`)

The one error registry and GameError (04 §7; frozen ABI codes: docs/spec/conformance/numeric-profile.md).

- **ErrorCode**: A stable machine error code (04 §7). Exactly the codes in protocol/error_registry.json, which gives each one's category and description; unknown codes are invalid.
- **ErrorRegistryEntry**: One entry of protocol/error_registry.json (04 §7): gameplay rejections, ABI or contract-validation failures (numeric-profile.md, protocol/), and evaluation faults that discard a whole proposal (04 §5.2).
- **GameError**: A typed error: a stable code, never English text to parse (04 §7). Per-code data fields are added, as optional properties, when a code first needs them (owner decision Q5, docs/decisions/owner-decisions-r3-2026-09-24.md).

## DomainEvent contracts (`protocol/event.schema.json`)

The DomainEvent envelope and registry, proposed versus committed (04 §1, §5.1, §8, §11; 14 §R3A).

- **CausationId**: The CommandId or EventId that caused this value (04 §11). Lowercase hyphenated UUID, any version.
- **CommittedEvent**: A DomainEvent after its enclosing commit succeeded (04 §5.1): the same value, with the committed revision. Only this form may be traced, projected or fanned out.
- **CorrelationId**: Shared by every event, effect and message derived from one command (04 §11). Lowercase hyphenated UUID, any version.
- **DomainEvent**: A typed fact from deterministic evaluation (04 §8). Inside a decision it is PROPOSED: it may drive in-decision reducers but MUST NOT be published, projected or sent anywhere (04 §5.1). It becomes observable only as a CommittedEvent. scope is semantic, not a broadcast audience (04 §8). position is the monotonic causal position in the decision (04 §5.2). 04 §8's subject_id lives in each typed payload that has a subject, where it is required.
- **EventId**: A DomainEvent, created from IdSource (01 A8). Lowercase hyphenated UUID, any version.
- **EventPayload**: The registered event types (04 §8) the R6P proof uses (pre-release-proof.md). Content-declared custom events are an R3B envelope.
  - `entity_entered_room`: entity_id entered room_id.
  - `item_acquired`: item_id is now held by holder_id.
  - `item_dropped`: item_id was dropped into room_id.
  - `quest_activated`: A QuestInstance became active.
  - `quest_resolved`: A QuestInstance resolved with a named outcome.
  - `choice_opened`: A pending choice opened.
  - `choice_resolved`: A pending choice resolved.
  - `fact_changed`: A fact changed from old to new (03 §7). subject_id is present exactly when the fact.assign that changed it had one.

## Fact contracts (`protocol/fact.schema.json`)

FactSpec and scoped facts (03 §7, §13; 21 §3.9, §4 Fact).

- **FactSpec**: A typed, namespaced fact declaration (03 §7): key (the fact's DefinitionRef is cartridge@version:fact/key; the cartridge is the namespace, 05 §4), versioned type, default, allowed scope kinds (a set) and meaning. Transition constraints and the reference graph are added with the compiler (R4).
- **FactType**: A fact's value type and default (03 §7). The types chapter one declares (00a §6): bool, enum over Keys, and int with optional inclusive bounds. The value itself is a FactValue (delta.schema.json).
  - `bool`: true or false.
  - `enum`: One of values (order and duplicates carry no meaning); default is one of them, which the compiler checks.
  - `int`: A safe integer within the optional inclusive bounds; the compiler checks default against them.
- **ScopedFact**: One stored fact value (03 §13): unique by fact, scope and subject_id within its world context, the same identity as the fact MutationTarget (delta.schema.json). An unset fact has its FactSpec default and no record. Revision and timestamps are host persistence metadata, not portable state.

## Feature envelopes (`protocol/feature.schema.json`)

R3B versioned feature envelopes (14 §R3B): the closed kind list, a version, and each kind's registration in protocol/feature_registry.json. - **FeatureKind**: One R3B feature kind (14 §R3B). Exactly the kinds in protocol/feature_registry.json, which gives each one's spec section and freeze milestone; unknown kinds are invalid. A reference to a feature definition is a DefinitionRef whose kind is one of these values (05 §4).
- **FeatureRegistryEntry**: One entry of protocol/feature_registry.json: a kind, the spec section that defines it, and the milestone that freezes its fields (14 §R3B).

## GameView contracts (`protocol/gameview.schema.json`)

The portable GameView envelope and its freshness (04 §14-§16; 00 §4.10; pre-release-proof.md P5). One schema for Story and Realm hosts; React Native renders it and never re-derives legality (04 §15).

- **AdvertisedAction**: One action of a resolved ActionSet (04 §19), for the entity or place it is listed under, with what the client needs to build its ActionInvocation (04 §2, §17) without a handwritten per-action catalog: the target spec (an entity target is the entity it is listed under) and the input parameters it requires, both from its ActionDefinition (action.schema.json). Lists are in presentation order, highest priority first (00 §4.10).
  - `true`: Offered and currently legal.
  - `false`: Shown but not legal now, with the typed reason (00 §4.10: greyed with the reason). Never a security boundary: the authority revalidates (ACT-09).
- **ChoiceOption**: One option of a pending choice: choosing it invokes choose with this choice_id.
  - `true`: Offered and currently legal.
  - `false`: Shown but not legal now, with the typed reason (00 §4.10: greyed with the reason). Never a security boundary: the authority revalidates (ACT-09).
- **EntityView**: A visible entity (04 §14): the view model, never internal component state. Only entities the actor's AudiencePolicy admits appear (03 §6).
- **ExitView**: One exit of the current place (04 §14; 00 §4.10 compass: disabled when unavailable, badge when locked), with the typed reason when moving through it is not legal now.
  - `true`: Moving through it is legal now.
  - `false`: Shown but not legal now, with the reason. Never a security boundary (ACT-09).
- **GameView**: One actor's semantic view (04 §14, §15): the current logical time (to build wait until, P5), the place, its exits, place-level actions, visible entities with their actions, the actor's inventory, quest journal, and the pending choice when one is open. The fields the R6P touch path needs (00 §4.10; P5); map, equipment, shop and other surfaces join with their capabilities.
- **GameViewSnapshot**: An authoritative GameView snapshot (04 §16). format versions the envelope: a new field or meaning takes a new format. projection_sequence orders this client stream's projection messages; a gap means resync from a fresh snapshot. view_freshness_token is opaque, echoed in ActionInvocation (same 1-128 character limit) for staleness diagnosis. Neither equals an authority revision (04 §16). Incremental projection messages are added with the Realm transport. narration holds committed narration records the client has not yet acknowledged, oldest first; the acknowledgement protocol arrives in R6.
- **NarrationRecord**: The committed narration of one accepted command, as this actor sees it: the lines of that command's DecisionResult narration (decision.schema.json), keyed by its command_id (06 §43: required narration is committed with its consequence as a stable record of pinned text keys and bindings; 04 §5.2 steps 7-8). Redisplay is read-only. A retry of that command replays its receipt and returns this same record with a current GameView (06 §43; 03 §14).
- **PendingChoice**: The actor's open choice (04 §15 'dialogue choices currently available'; 06 §43): its prompt (the line or scene text shown above the options), the speaking participant when there is one, the options in presentation order, and whether the player may close it without choosing (the close_choice command; 06 §43: never trapped in a modal screen, and closing does not change the outcome).
- **PlaceView**: The current place (04 §14 room).
- **QuestView**: A journal entry (04 §15 'quest journal state'; 00 §4.10 Journal).
- **UnavailableReason**: Why an action, choice or exit is shown but not legal now (00 §4.10: greyed with the reason, badge when locked; P5 'clear unavailable-action feedback'): the typed code, and optionally the player-facing sentence that tells apart two reasons with one code (a locked door, a causeway under the tide). A GameView presentation field, so GameError and the error registry stay unchanged.

## Identity contracts (`protocol/identity.schema.json`)

Definition identity and runtime identities (03 §2, §3, §6; 05 §4). Each id is its own named type; the types are not interchangeable (03 §6).

- **AuthorityDomainId**: The current serialized mutation-ownership domain (03 §6). Distinct from WorldContextId: one logical world can hold many authority domains. Lowercase hyphenated UUID, any version.
- **CartridgeId**: A cartridge identity (05 §3 id, 05 §4), lowercase snake_case, at most 64 characters.

- **RealmId**: The broader persistent Realm identity (03 §6); the id of realm StateScope. Lowercase hyphenated UUID, any version.
- **ReleaseVersion**: A release version (05 §3 version, §12): MAJOR.MINOR.PATCH without leading zeros, pre-release or build metadata, at most 64 characters.
- **WorldContextId**: Logical world/context identity: the simulation, save or deployment context in which state exists (03 §6, 'Logical world identity is not mutation-owner placement'). Never a fencing, owner or shard token. Lowercase hyphenated UUID, any version.

## Manifest contracts (`protocol/manifest.schema.json`)

Cartridge, deployment and campaign manifests and their version fields (05 §3, §20, §22; 07 §15 campaign manifest; 01 A5). Each version field owns one thing; none stands in for another (05 §3 'Version vocabulary').

- **ApiVersion**: api_version: the authored source document/schema family (05 §3).
- **CampaignId**: A campaign identity (07 §15), lowercase snake_case, at most 64 characters.
- **CampaignManifest**: A versioned campaign manifest (07 §15, 05 §23): the exact cartridge releases a save lineage composes, at least one. An expansion changes this manifest, never an existing artifact.

- **CartridgeRelease**: An exact immutable cartridge release: cartridge_id@version names exactly one semantic hash (05 §12).

## Observation contracts (`protocol/observation.schema.json`)

The one observation record format, its stores and correlation ids, and the game-trace entry (11 §11-§15; ADR-075, docs/decisions/adr-075-observability-proposal.md). Observation is never authority.

- **AgentWork**: One agent's work on one pull request: its role, model (opus, fable, astra, ...), instance (1, 2, ... among that role's agents on the pull request, so (pull_request, role, instance) is unique), the tokens it used (a required Measure; unknown when not reported, never 0) and the pull request's disposition (merged or closed), which is not a judgment of the agent's work. Evidence for analysis, never an acceptance authority.
- **BuildIds**: The correlation ids of a content diagnostic: the source revision; input_digest, the SHA-256 of the input the producer read (the compiler: the canonical JSON object mapping each source file's cartridge-relative path to the SHA-256 of its bytes; the loader: the artifact file's bytes; the known answer arrives with the first producer), which exists even when the input does not parse; and content_hash only once an artifact's cartridge hash exists, never a stand-in for it.
- **CommitOutcome**: What happened to the command's commit (04 §5.1; 03 §14, §15): committed at revision (the revision after; a rejection receipt does not advance it) with the committed events in order and the effect ids; failed (definitively rolled back) with its cause: injected (by the run's fault schedule) or storage_error (the store reported failure; host detail goes to operations); unknown (the outcome could not be observed; reconciled under 03 §15, never presumed rolled back) with its cause: injected or no_outcome (no answer from the store: crash, kill, lost acknowledgement); or unavailable (not_applicable: nothing was committed, such as a fault or a rejection without a receipt). Failed and unknown carry no events or effects: proposed events never leave a failed commit (04 §5.1). The allowed decision and commit pairs: ADR-075 §4.
  - `committed`
  - `failed`
  - `unknown`
  - `unavailable`
- **EventName**: An event or metric name (11 §12): two or three lowercase snake_case segments joined by dots, area first. The registered names are protocol/event_registry.json, which must equal the ObservationRecord branches.
- **EventRegistryEntry**: One entry of protocol/event_registry.json: a name, its store, whether it is an event or a metric (a metric's data is a Measure; the description gives its unit), and a description citing the spec and naming its producers.
- **HostIds**: The correlation ids of an operations record: the code revision, the host kind, and the run and command the measure joins (the trace carries the rest).
- **HostKind**: Which host ran the code: a kind, never a device identity (AGENTS.md: no serials, UDIDs or device names).
- **InvariantFailure**: A registered invariant (protocol/invariants.json id) that failed after the command in ids (09 §2 expected and observed invariant: the invariant is the expectation; the record is the observed failure).
- **KernelVersion**: The source revision that produced a record (11 §11 kernel version; 09 §2 engine/kernel revision): the kernel id (kernel/ts/src/index.ts KERNEL_ID), @, and the full git commit; kernel, compiler and hosts build from one commit. The bare form only from a clean tree at that commit; a tree with uncommitted changes appends -dirty, and such a record is never an exact repro key. Reporting HEAD for a dirty tree is forbidden. It names source, not a fingerprint of a built artifact.
- **LookupWord**: One word of a failed lookup as the producer recorded it: the normalized word (lowercase letters and digits, at most 32), or redacted when it held a host identifier (ADR-075 §6) or anything else a record may not carry. Redaction happens before the record is built; a redacted word is marked, never an empty string.
  - `word`
  - `redacted`
- **Measure**: A measured quantity, never a bare number: observed with a non-negative integer value, unknown (it applies but could not be observed; never 0), or unavailable with its cause (never empty or absent).
  - `observed`
  - `unknown`
  - `unavailable`
- **ObservationFormat**: The format tag of every observation record. A new field or meaning takes a new tag.
- **ObservationRecord**: Every observation record, one per JSON Lines line in canonical encoding (ADR-075 §1): the format tag, the registered event name, its store, the store's closed correlation ids and the event's data. One branch per protocol/event_registry.json entry.
  - `trace.run`
  - `trace.command`
  - `content.diagnostic`
  - `simulation.invariant_failed`
  - `target.unresolved`
  - `kernel.decision_latency`
  - `agent.work`
- **ObservationStore**: The store a record belongs to (ADR-075 §2): game_trace (per-command decisions, host-independent, 11 §15), diagnostics (things to fix: 08 §6 diagnostics and simulator failures), operations (host timings, 11 §13), dev_evidence (agent work cost and outcome).
- **ReplayIds**: The correlation ids of a record that must reproduce by deterministic replay (09 §2): the cartridge hash, the code revision, the run's initial RNG state, the run (a save lineage; for the simulator, one sequence), the command, and the authority revision the command was decided against. Local ids only: no host, device, account or time.
- **RngDraw**: One bounded uniform draw (09 §4 draw trace; numeric profile): its bound and the value drawn, value below bound.
- **RngTrace**: The RNG draws of an accepted decision, in draw order (11 §15 'RNG draws if configured'; 09 §4): observed (draws [] is a decision that drew nothing), unknown (collection was on but could not supply a complete list), or unavailable (not_collected: collection was off).
  - `observed`
  - `unknown`
  - `unavailable`
- **RunHeader**: The replay header of one run (09 §2; ADR-075 §4), written once before its first trace.command: world_context_id, the logical world the run's fresh state and every id are minted in (so a run with no commands still reconstructs its initial world; ADR-075 amendment 2026-09-25, R5 S1 review A4); with its ids (cartridge, source revision, seed, run) and the ordered commands of the run's trace.command entries, the complete replay input. initial_state: fresh (the cartridge's initial state) or unavailable, not_collected (a start from a snapshot, whose identity is not recorded until R6 checkpoints define one). fault_schedule: the SHA-256 of the canonical fault schedule R6 fault simulation defines, or unavailable (not_applicable) when none is injected.
- **RunIds**: The correlation ids of a run header, and of a failed lookup in that run (target.unresolved): the replay inputs a run shares (ReplayIds without command and revision).
- **TargetUnresolved**: A player's lookup that resolved to no target or to several (21 §7 none | ambiguous; 04 §18), so no Command was built and nothing reached the game_trace (owner request, R5 S2: the Lab, bots and tests see what players try that the content lacks). room: the room it was tried in; outcome and candidates: the resolution and its candidate count (0 for none); words: the normalized words compared, after redaction, at most 16; after_ordinal: the ordinal of the run's last trace.command before it (0 before the first), joining it to the game_trace by run_id.
- **TraceDecision**: The decision outcome of a traced command (DecisionResult, 04 §5), compact: accepted with its typed outcome, the state delta digest (SHA-256 of the canonical bytes of its StateDelta, the content_hash construction; its known answer arrives with the first producer), its RNG draws and the RNG state it returned (DecisionResult.rng; the delta does not cover it); rejected with its GameError; or fault with its ErrorCode and, when bound, its target (04 §5.5).
  - `accepted`
  - `rejected`
  - `fault`
- **TraceEntry**: One game-trace entry (11 §15; 09 §7): its ordinal (1, 2, ... in the run's command order, binding it to the run's trace.run header), the full Command (command.id equals ids.command_id), the decision, and the commit outcome, for accepted and rejected decisions and failed commits alike. Derived, never authority. No time, duration, host or device field: entries are identical across hosts given identical complete replay inputs and controlled faults (ADR-075 §4).
- **UnavailableCause**: Why a value is unavailable: not_applicable (it does not apply here, such as a commit for a fault), not_collected (collection is off, such as RNG draws when the draw trace is not configured).
- **WorkIds**: The correlation id of a dev-evidence record: the pull request of the work on lorecrafting/lokacore.

## Room and connection contracts (`protocol/room.schema.json`)

The room (place) definition kind and its exits (21 §5 Place/Room, Connection; 05 §17; 00 §4.1, §4.10; 00a §2, §12), owned by movement (capability_registry.json). R5 slice 1: what look and move need; slice 2: inspectable details. Tags, description variants and barriers join with their capabilities as optional fields, which keep the loka-cartridge-v2 tag (CompiledCartridge compatibility rule); contents are derived from containment (03 §23), not stored in the room.

- **Alias**: A word or phrase a player types to name a detail (21 §6 aliases; 04 §18 aliases): lowercase letters and digits, the words of a phrase joined by _ (the player's `mooring post` is compared as mooring_post; kernel/ts/src/target.ts gives the normalization). At most 64 characters.
- **Connection**: One directed exit to another room of the same cartridge (21 §5 Connection; 05 §17). Its identity is its room and direction, so a later optional barrier field (a DefinitionRef to one shared Barrier state, 21 §5 Barrier; 05 §25 coherent connections) adds state without changing what an exit without one means. A reciprocal exit is authored in the destination room (00a §2).

Custom named connections (05 §17) join later as a separate optional field.

Localized text as string ids plus bindings (04 §15; 05 §18; 06 §43), shared by GameView and DecisionResult narration.

- **Text**: Localized text: a string id and its named bindings (04 §15 'localized string IDs plus interpolation data'; 06 §43 'pinned text keys and bindings'). Binding names are lowercase snake_case, at most 64 characters.
- **TextCatalog**: The cartridge's default-locale strings (05 §18: stable string ids, inline defaults extracted into a catalog): each TextKey to its display text, 1 to 4,096 characters. One locale only; per-locale catalogs, plural rules and binding placeholders join later under a new cartridge format tag. Every text key a room (title, description) or an action (label, accessibility) uses has an entry; the compiler and loader report a missing one as UNRESOLVED_REFERENCE.
- **TextKey**: A localization string id, never display text (04 §15; 05 §18): lowercase dotted snake_case of at most 128 characters, the ActionDefinition label rule. Text carries its interpolation bindings.
- **TextValue**: A value interpolated into localized text (04 §15 'interpolation data'; 06 §43 'bindings'): a TextKey (localized in turn, so a Key such as a direction also fits), an integer (a count, a time) or a boolean.
