# PageFlip Animation Reference

## Animation Types (4 total)

Generated by `page_rigger.gd` `_generate_animations_logic()`. All 4 are always generated together.

### 1. `turn_flexible_page` (forward, flexible)
- **Root bone (x=0):** Rotates 0° → lift (-15°) → midpoint (-90°) → land (~-170°) → flat (-179.9°)
- **Surface bones:** Add curl/bend on top of root rotation. Influenced by `paper_stiffness`, `lift_bend`, `land_bend`
- **Curl effect:** Rows animate with time offset based on `curl_mode` (TOP_CORNER_FIRST, BOTTOM_CORNER_FIRST, STRAIGHT)
- **Visual:** Page curls off the right side, sweeps through vertical, lands on left side with organic paper bending
- **Used for:** Normal forward page turns (non-cover pages)

### 2. `turn_flexible_page_mirror` (backward, flexible)
- Same as above but mirrored: starts from left (-179.9°), sweeps to right (0°)
- **Used for:** Normal backward page turns

### 3. `turn_rigid_page` (forward, rigid)
- **Root bone (x=0):** Rotates 0° → -90° → -179.9° (smooth, no lift/land phases)
- **Surface bones:** ALL stay at 0° (no bending at all)
- **Visual:** Page rotates as a flat plane around the spine axis, like a hard cover
- **Used for:** Cover page turns when `covers_are_rigid = true`

### 4. `turn_rigid_page_mirror` (backward, rigid)
- Mirror of rigid: -179.9° → -90° → 0°
- **Used for:** Cover page turns backward

## Bone Architecture

- Bones arranged in a grid: `subdivision_x + 1` columns x `subdivision_y + 1` rows
- Default: 8x5 = 9 columns x 6 rows = 54 bones
- Column 0 = root bones (at x=0, the spine). Each row has its own root bone
- Columns 1+ = surface bones (children of root, chain outward from spine)
- Root bone rotation drives the main page sweep
- Surface bone rotation adds curl/bend effects on top

## Animation Timeline (Flexible)

```
0.0          0.15          0.5          0.85          1.0
|--- LIFT ---|---- RISE ----|---- FALL ----|--- LAND ---|
flat right    peak curl     vertical      settling     flat left
(0°)         (-15°+bend)   (-90°)        (~-170°)     (-179.9°)
                            ↑
                    midpoint signal fires
                    (change_page_requested)
```

## Key Signals & Methods

- `change_page_requested` — fires at animation midpoint (0.5). DynamicPage signal.
- `end_animation` — fires at animation end (1.0). DynamicPage signal.
- `started_page_flip_animation` — PageFlip2D signal, emitted when `_start_animation` begins
- `ended_page_flip_animation` — PageFlip2D signal, emitted in `_on_animation_finished`

## Slot Architecture

| Slot | Node | Z-Index | Purpose |
|------|------|---------|---------|
| Slot 1 | `_slot_1` → `static_left` (Polygon2D) | 1 | Static left page |
| Slot 2 | `_slot_2` → `static_right` (Polygon2D) | 1 | Static right page (visible underneath during turn) |
| Slot 3 | `_slot_3` → `dynamic_poly` front_texture | 10→25→10 | Animated page Face A (front of turning page) |
| Slot 4 | `_slot_4` → `dynamic_poly` back_texture | (same poly) | Animated page Face B (back of turning page) |

- `static_right.texture` = new content (visible underneath as page lifts)
- `dynamic_poly` shows Face A (current content) during first half, Face B (new content back) during second half
- Shader detects front/back via `dFdx(UV)` cross product (face winding direction)

## Single-Page Mode Problem

The entire animation rotates around x=0 (spine). In a normal book, both pages are visible so the full sweep looks natural. In single-page mode:

- **First half (0° to -90°):** Page lifts off right side — GOOD, visible content curling up
- **Second half (-90° to -180°):** Page lands on left side — BAD, shows warped text in the left margin area

Camera framing (`_adjust_camera_for_single_page`) has ~5% margin, AND on portrait mobile screens the horizontal space exceeds page width significantly, so deformed content past x=0 IS visible.

## Approaches for Single-Page Fix

### A. Half-Animation + Snap
Play real PageFlip animation, stop at midpoint, snap to new content.
- Pro: Real bone deformation visible, simplest to implement
- Con: Only see lift phase, no landing

### B. SubViewport Clipping
Render the full animation inside a SubViewport sized to page bounds, display as texture.
- Pro: Full animation visible but naturally clipped
- Con: Extra viewport overhead, positioning complexity

### C. Shader Screen-Space Clipping
Add `discard` in fragment shader when `SCREEN_UV.x` is past the spine threshold.
- Pro: Uses full animation, minimal perf cost
- Con: Need to compute correct threshold, SCREEN_UV behavior with Skeleton2D needs verification

### D. Custom "Right-Side Only" Animation
Modify animation keyframes so root bone only rotates 0° to ~-45° (doesn't cross spine), with increased surface bone curling to compensate.
- Pro: Full animation that stays on the right side
- Con: Requires modifying PageFlip internals, may not look like a real page flip

### E. Rigid Board + Half-Animation
Use RIGID_BOARD preset (no bending) + stop at midpoint. Simple flat rotation.
- Pro: Cleanest look, no warped text artifacts
- Con: Less visually interesting than flexible curl
